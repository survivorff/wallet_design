# 黑名单与风险地址库：链上情报

## 一句话总结

链上情报（threat intelligence）是钱包安全的"免疫系统"——通过实时识别恶意地址、合约、域名，在用户犯错前阻止攻击。

## 链上情报的类型

### 1. 恶意地址数据库

```
分类：
- 已知钓鱼地址（黑客地址）
- 黑名单地址（OFAC 制裁等）
- 已被报告的诈骗地址
- 混币器地址
- 高风险地址（高度匿名化使用）

数据维护：
- 用户举报
- 安全公司监控
- 链上行为分析
- 跨平台数据共享
```

### 2. 恶意合约数据库

```
分类：
- 已知漏洞合约
- 蜜罐合约（只能买不能卖）
- Rug Pull 合约
- 钓鱼合约（伪造的 DEX/桥）
- 升级权限不安全的合约

判断维度：
- 代码相似性（与已知恶意代码对比）
- 行为模式（异常的资金流出）
- 部署时间（新部署的合约风险高）
- 是否验证（未验证代码可疑）
```

### 3. 恶意域名数据库

```
分类：
- 钓鱼网站（仿冒正规 DApp）
- 恶意 Mint 网站
- 假空投网站
- 假客服网站
- 已下架但仍存活的网站

来源：
- 域名相似性扫描（unisawp.org → unisawp.com）
- 用户举报
- 安全公司爬虫
- 浏览器/钱包用户行为数据
```

### 4. 风险代币数据库

```
分类：
- 蜜罐代币
- 高税率代币（卖出时被收 99% 税）
- 高度集中持有的代币（少数地址持有大部分）
- 可被任意 Mint 的代币
- 低流动性代币
```

## 主要情报提供商

### 商业服务

```
Chainalysis：
- 行业最大的链上分析公司
- 服务对象：政府、银行、交易所
- 提供制裁筛查、AML 服务
- API/SaaS 形式

TRM Labs：
- 与 Chainalysis 类似
- 强项：金融犯罪分析
- 服务对象：金融机构

Elliptic：
- 老牌区块链情报公司
- 制裁、AML、风险评分

Forta：
- 实时威胁检测网络
- 去中心化的 bot 网络
- 监控所有链上活动
```

### 安全社区

```
SlowMist 慢雾（中国）：
- 安全审计 + 威胁情报
- 黑客地址追踪
- 钓鱼网站收集

PeckShield：
- 安全审计
- 黑名单数据
- 实时威胁情报

OpenZeppelin Defender：
- 智能合约监控
- 威胁检测
- 自动响应
```

### 开源/免费数据

```
Etherscan：
- 标记的地址（known address tags）
- 部分免费 API
- 用户可以举报

Blockscout：
- 部分链的开源浏览器
- 类似的标记功能

GoPlus Security：
- 开源安全数据
- 合约风险检测
- 代币安全检测
- 免费 API
```

## 钱包如何使用情报

### 集成方式

```
方式一：API 调用
- 实时查询第三方 API
- 优点：数据最新
- 缺点：依赖第三方、有延迟、成本

方式二：本地数据库
- 钱包内嵌或定期下载
- 优点：响应快、不依赖第三方
- 缺点：数据可能过时、占空间

方式三：混合
- 高风险数据本地（如 OFAC 制裁）
- 实时数据 API 查询（如 Forta 检测）
- 平衡性能和实时性

方式四：去中心化网络
- 多个数据源汇总
- 用户共享数据
- 还在探索中
```

### 应用场景

```
1. 转账时检查接收方
   - 警告："你正在转账给已知诈骗地址"
   - 阻止：高风险时不允许操作

2. 签名前检查合约
   - 警告："你正在与已知恶意合约交互"
   - 提示：合约的风险评分

3. DApp 浏览时检查域名
   - 警告："这是已知钓鱼网站"
   - 阻止：直接拦截访问

4. 资产展示时检查代币
   - 标记："蜜罐代币，可能无法卖出"
   - 隐藏：垃圾代币默认不显示
```

### 用户体验设计

```
警告分级：

ℹ️ 提示（信息）：
- "这是新合约"（< 7 天）
- 不阻塞操作

⚠️ 警告（建议谨慎）：
- "首次与该合约交互"
- "授权额度异常大"
- 用户可以继续

🟡 严重警告（强烈建议拒绝）：
- "合约有已知风险"
- "类似域名疑似钓鱼"
- 需要额外确认

🔴 危险（默认阻止）：
- "已确认的恶意地址"
- "已知钓鱼网站"
- 需要用户输入"我了解风险"才能继续

⛔ 制裁（直接阻止）：
- "OFAC 制裁地址"
- 完全禁止（合规要求）
```

## 数据共享与协作

### 行业协作的重要性

```
单个钱包的数据有限：
- 看到的攻击是片面的
- 钓鱼网站可能只在某些用户中传播
- 新出现的攻击难以检测

行业协作的价值：
- 共享黑名单数据
- 联合监控
- 快速响应

代表机制：
- ScamSniffer：开源钓鱼数据
- Web3 安全联盟
- 各种安全社区
```

### 隐私与共享的平衡

```
共享数据的隐私问题：
- 不能分享用户的具体行为
- 但可以分享聚合的威胁情报
- 区分"威胁数据"和"用户数据"

最佳实践：
- 只分享威胁特征（不是用户身份）
- 数据脱敏
- 明确的使用条款
```

## 误报与漏报

### 误报（假阳性）

```
问题：
- 把好地址标记为坏
- 用户被错误警告
- 影响用户体验
- 损害合法项目

例子：
- 新部署的合法合约被误标
- 类似名字的合法域名被误标
- 用户合法的反垄断行为被误标

应对：
- 多源数据验证
- 申诉机制
- 持续维护和更新
- 不要只依赖单一数据源
```

### 漏报（假阴性）

```
问题：
- 没识别出真正的恶意地址
- 用户没有得到警告
- 资产损失

原因：
- 新出现的攻击（数据库没收录）
- 攻击者用新地址（绕过黑名单）
- 数据库更新不及时

应对：
- 多数据源
- 实时检测（不只依赖历史数据）
- 行为分析（不只看身份）
```

## AI 在威胁情报中的应用

### 现状

```
AI 分析能识别：
- 异常的合约模式（机器学习）
- 可疑的资金流（图分析）
- 钓鱼网站特征（视觉识别）
- 异常的用户行为（异常检测）

代表项目：
- Forta 的部分 bot
- 一些钱包内置的 AI 检测
- 安全公司的内部工具
```

### 未来方向

```
更先进的 AI 应用：
- 实时合约代码分析（不只是字节码相似性）
- 自然语言理解（理解 DApp 的真实意图）
- 多模态分析（结合代码、行为、社交信号）
- 大模型增强的威胁分析

挑战：
- 误报率
- 解释性（用户为什么看到这个警告）
- 对抗性攻击（攻击者绕过 AI）
```

## 钱包的最佳实践

### 1. 多源数据集成

```
不依赖单一数据源：
- 商业服务（如 Chainalysis）
- 安全公司（如 SlowMist）
- 开源数据（如 GoPlus）
- 自有检测

多个数据源交叉验证，减少误报和漏报
```

### 2. 实时性

```
威胁情报必须实时：
- 钓鱼网站平均存活 < 24 小时
- 攻击者频繁换地址
- 黑名单需要快速更新

实现方式：
- API 实时查询（核心威胁）
- 频繁更新本地数据（每小时/每天）
- 推送机制（紧急威胁）
```

### 3. 用户友好

```
警告设计：
- 清晰说明风险
- 给出具体建议
- 不要"狼来了"（过度警告）
- 让用户能区分轻重

教育用户：
- 解释为什么有这个警告
- 帮助用户做正确决策
- 不要 paternalize
```

### 4. 持续投入

```
威胁情报是持续的工作：
- 新攻击不断出现
- 数据库需要持续维护
- 检测算法需要升级
- 用户教育需要持续

不能"做一次就完了"
```

## 小结

链上情报和黑名单是钱包安全的关键基础设施。它的作用：

1. **预防**：在用户犯错前提示
2. **检测**：发现异常行为
3. **响应**：快速更新威胁数据
4. **教育**：帮助用户理解风险

理想状态是：用户在使用钱包时几乎感觉不到威胁存在——不是因为没有威胁，而是因为钱包在背后默默拦截了大部分。但这需要：
- 强大的数据源
- 准确的检测
- 友好的用户体验
- 持续的投入

钱包能否做好这一点，直接关系到用户是否能在 Web3 中安全地操作。这是钱包产品的核心能力之一，也是真正的差异化所在。
