# 钓鱼攻击：假网站、恶意签名、地址投毒

## 一句话总结

钓鱼是 Web3 用户资产损失的第一大原因——攻击者不需要破解任何技术，只需要让用户"自愿"签署一笔恶意交易。

## 钓鱼攻击的规模

```
2023-2024 年钓鱼攻击数据（估计）：
- 年度总损失：$500M+
- 单次最大损失：数千万美元（鲸鱼被钓）
- 日均受害者：数百人
- 钓鱼网站存活时间：平均 < 24 小时（但足够造成损失）
```

## 攻击类型详解

### 类型一：假网站钓鱼

```
攻击链：
1. 创建假网站（与真实 DApp 视觉一致）
2. 推广假网站（Google 广告、Twitter 广告、假空投链接）
3. 用户访问假网站
4. 假网站请求连接钱包
5. 用户连接（此时还没有损失）
6. 假网站请求恶意签名
7. 用户确认签名
8. 资产被盗

常见的假网站类型：
- 假 DEX：uniswap → un1swap, uniswap.com（真实是 .org）
- 假空投：claim-xxx-airdrop.com
- 假 Mint：bayc-official-mint.xyz
- 假桥：bridge-ethereum.io
- 假工具：revoke-approvals.com（讽刺：假装帮你撤销授权）
```

### 类型二：恶意签名请求

#### Approve 钓鱼

```solidity
// 攻击者请求用户签署：
token.approve(attackerAddress, type(uint256).max)

// 效果：攻击者获得无限额度的代币转移权限
// 之后攻击者调用：
token.transferFrom(victim, attacker, victim.balance)
```

#### Permit 钓鱼（更隐蔽）

```solidity
// EIP-2612 Permit：链下签名，链上执行
// 用户签署一条消息（不是交易，不花 Gas）
// 攻击者拿到签名后在链上执行：

token.permit(victim, attacker, amount, deadline, v, r, s)
// 然后：
token.transferFrom(victim, attacker, amount)

// 危险之处：
// - 用户签的是"消息"不是"交易"，心理防线更低
// - 不花 Gas，用户可能觉得"签个名没什么"
// - 签名可以被攻击者保存，择机执行
```

#### setApprovalForAll 钓鱼

```solidity
// 针对 NFT 的攻击：
nftCollection.setApprovalForAll(attackerAddress, true)

// 效果：攻击者可以转走用户在该集合中的所有 NFT
// 一次签名，所有 NFT 都暴露
```

#### eth_sign 盲签

```
// 最危险的签名类型：签署任意数据
// 用户完全看不懂签的是什么
// 可能是：交易、授权、任何东西

// 很多钱包已经默认禁用 eth_sign
// MetaMask 2023 年起默认禁用
```

### 类型三：地址投毒

```
攻击流程：

1. 攻击者监控目标地址的交易
   目标经常向 0xAbCd...1234 转账

2. 攻击者生成相似地址
   生成 0xAbCd...1234（首尾相同，中间不同）
   这需要大量计算但是可行的（vanity address 生成）

3. 攻击者从相似地址向目标发送 0 金额交易
   或发送极小金额的代币

4. 目标的交易历史中出现了这个"熟悉"的地址

5. 目标下次转账时从历史记录复制地址
   复制了攻击者的地址而非真实地址

6. 资产转到攻击者地址

防御：
- 显示完整地址（不要只显示首尾）
- 地址簿功能
- 标记 0 金额转入为可疑
- 转账前与上次地址全文对比
```

### 类型四：社交工程钓鱼

```
场景 A：假客服
- 用户在 Discord 提问
- "官方客服"私信用户
- 引导用户访问"修复工具"网站
- 网站要求输入助记词

场景 B：假空投
- 社交媒体宣传"大额空投"
- 引导用户连接钱包"领取"
- 实际是签署恶意授权

场景 C：假合作
- 冒充项目方联系 KOL/开发者
- 发送"合作文档"（实际是恶意文件）
- 或引导安装"测试版 App"（恶意软件）

场景 D：Ice Phishing
- 在合法 DApp 的社区中发布假链接
- 利用社区信任降低用户警惕
```

## 钱包的防御措施

### 1. 签名前防御

```
交易模拟：
- 每笔交易签名前自动模拟
- 显示资产变化预览
- 异常变化高亮警告

风险评估：
- 目标地址是否在黑名单
- 合约是否刚部署（< 7 天）
- 是否请求无限授权
- 是否是 Permit 签名
- 域名是否与已知 DApp 相似

用户提示：
- "这是你第一次与此合约交互"
- "此操作将授权转移你所有的 XXX"
- "此签名可能允许他人花费你的代币"
```

### 2. 签名时防御

```
分级确认：
- 低风险操作：正常确认按钮
- 中风险操作：额外警告 + 确认
- 高风险操作：需要输入"CONFIRM"或等待倒计时
- 极高风险：强烈建议拒绝，需要多步确认

信息展示：
- 用人类语言描述操作含义
- 显示美元价值（不只是代币数量）
- 对比"操作前"和"操作后"的状态
```

### 3. 签名后防御

```
授权监控：
- 定期扫描用户的所有授权
- 发现异常授权立即通知
- 提供一键撤销功能

交易监控：
- 监控用户地址的异常转出
- 大额转出立即推送通知
- 可疑操作后建议检查授权
```

### 4. 教育与预防

```
用户教育：
- 首次使用时的安全教育
- 遇到高风险操作时的即时教育
- 定期的安全提醒

预防措施：
- 默认禁用 eth_sign
- Approve 默认建议精确金额（而非无限）
- 首次大额转账建议先发小额测试
- 提供"安全模式"（限制可交互的合约）
```

## 行业协作

### 黑名单共享

```
数据来源：
- 用户举报
- 安全公司监控（SlowMist、PeckShield、Chainalysis）
- 链上行为分析（自动检测恶意合约）
- 社区贡献

共享机制：
- 钱包之间共享恶意地址/域名数据
- 开放的黑名单 API
- 实时更新（钓鱼网站存活时间短，需要快速响应）
```

### 标准化

```
需要标准化的内容：
- 风险等级定义（什么算"高风险"）
- 签名请求的展示格式
- 黑名单数据格式
- 安全提示的措辞规范
```

## 小结

钓鱼攻击是 Web3 安全的"第一杀手"，原因很简单：它攻击的是人，而不是技术。

钱包能做的最有价值的事：
1. **让用户看懂**自己在签什么（交易模拟 + 语义化展示）
2. **在异常时拦截**（风险评估 + 分级确认）
3. **减少攻击面**（禁用危险功能 + 默认安全设置）
4. **快速响应**（黑名单实时更新 + 社区协作）

完全消除钓鱼是不可能的（因为它利用的是人性），但好的钱包设计可以大幅降低用户上当的概率。
