# 社交恢复与备份策略：丢了私钥怎么办

## 一句话总结

"丢了私钥就丢了一切"是 Web3 最大的用户痛点之一——好的恢复机制是让钱包从"赌博工具"变成"日常工具"的关键。

## 备份方案对比

### 方案一：助记词（传统）

```
机制：用户抄写 12/24 个英文单词
恢复：在新设备输入助记词

优点：
✅ 完全自主，不依赖任何服务
✅ 跨钱包通用（BIP-39 标准）
✅ 概念简单（虽然实操复杂）

缺点：
❌ 用户保管能力差（纸质备份易丢）
❌ 抄写易错（一个字母错就完蛋）
❌ 数字化保存有泄露风险
❌ 全有或全无（要么完整恢复，要么完全失败）
```

### 方案二：Keystore + 密码

```
机制：私钥用密码加密成 JSON 文件
恢复：导入 JSON + 输入密码

优点：
✅ 文件可以多份备份
✅ 即使文件泄露，没密码也无法使用

缺点：
❌ 还是要记住密码（密码忘了 = 丢失）
❌ 弱密码可被暴力破解
❌ 不如助记词通用
```

### 方案三：社交恢复（合约钱包）

```
机制：指定多个监护人，多数同意可恢复

设置：
- 监护人 1：朋友 A 的地址
- 监护人 2：硬件钱包
- 监护人 3：另一个邮箱关联的地址
- 阈值：2/3

恢复流程：
1. 用户在新设备生成新密钥
2. 请求监护人确认（链上签名或链下验证）
3. 达到阈值 → 钱包合约更新签名者
4. 新密钥获得控制权

优点：
✅ 不依赖单点（监护人之一丢失没关系）
✅ 不需要记忆助记词
✅ 可以选择不同的"监护人组合"

缺点：
❌ 需要设置（用户教育成本）
❌ 监护人需要响应（社交协调）
❌ 仅适用于合约钱包
```

### 方案四：MPC 分片备份

```
机制：私钥被分成 N 片，分布存储

典型 2/3 分片：
- 分片 1：用户设备
- 分片 2：服务商（云端加密）
- 分片 3：用户的备份（可以是另一个设备、邮箱关联等）

恢复：任意 2 片协作即可恢复签名能力

优点：
✅ 无助记词，体验流畅
✅ 单点故障不致命
✅ 可以更换分片（不影响地址）

缺点：
❌ 依赖服务商（如果是 2/3 含服务商）
❌ 实现复杂，闭源风险
```

### 方案五：Passkey + 平台同步

```
机制：私钥在设备 Secure Enclave 中，通过 iCloud Keychain / Google 同步到其他设备

恢复：登录平台账号即可在新设备使用

优点：
✅ 用户体验最佳（无需任何主动备份）
✅ 硬件级安全
✅ 跨设备无缝

缺点：
❌ 依赖平台（Apple/Google）
❌ 平台账号被攻破 = 钱包被攻破
❌ 跨平台同步不完美（Apple ↔ Google）
```

## 多重备份策略

### 不要把鸡蛋放一个篮子

```
推荐的多重备份方案（针对持有大额资产）：

主钱包：合约钱包（社交恢复 + 多签）
├── 主签名者：日常使用的设备 Passkey
├── 监护人 1：硬件钱包
├── 监护人 2：另一台设备（手机/电脑）
└── 监护人 3：可信家人/朋友

冷备份：
├── 助记词抄写（金属板，防火防水）
└── 存放在不同地点（银行保险箱、家中保险柜）

意外应急：
├── 委托律师（持有恢复指令的封缄信）
└── 死亡开关（一段时间未活动则触发恢复）
```

## 产品设计要点

### Onboarding 时的备份引导

```
错误的做法（强制立刻备份）：
- 创建钱包后立即弹出助记词
- 强制用户抄写 + 验证
- 用户烦躁，可能选错单词、放弃创建

更好的做法（渐进式）：
- 创建钱包后立即可用（用 Passkey 或社交登录）
- 资产到一定金额后提示设置备份
- 提供多种备份选项
- 解释每种选项的优劣
```

### 恢复体验设计

```
理想的恢复流程：

1. 用户在新设备打开钱包
2. 选择"恢复钱包"
3. 输入邮箱 / 扫码 / 选择恢复方式
4. 验证身份（监护人确认 / 平台账号 / 助记词）
5. 完成恢复

关键设计：
- 不要让用户在压力下操作（丢了钱包很焦虑）
- 提供清晰的指引和反馈
- 支持多种恢复方式（用户可能记得一种忘了另一种）
- 24/7 客服支持（虽然钱包不"管钱"，但用户需要心理支持）
```

## 备份提醒策略

```
触发提醒的时机：

1. 资产首次超过 $100：建议设置基础备份
2. 资产首次超过 $1,000：建议设置社交恢复
3. 资产首次超过 $10,000：建议硬件钱包 + 多签
4. 30 天未备份检查：提醒确认备份还可用
5. 重大产品更新：提醒重新评估备份策略

提醒方式：
- 应用内横幅（不打扰但持续提示）
- 关键操作前的确认页（"你的备份是否安全？"）
- 邮件/通知（针对长期未操作用户）
```

## 小结

恢复机制是钱包从"小众工具"走向"主流产品"的关键瓶颈。理想的设计应该：

1. **不强制立刻备份**：让用户先体验产品
2. **提供多种选择**：不同用户有不同偏好
3. **渐进式引导**：随着资产增长升级备份策略
4. **降低恢复门槛**：恢复时用户已经很焦虑，不要再增加难度

最好的备份是"用户没意识到自己在备份"——Passkey + 平台同步 + 社交恢复的组合正在朝这个方向努力。
