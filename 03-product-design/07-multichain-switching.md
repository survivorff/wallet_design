# 多链切换与链抽象：用户不应该知道自己在哪条链

## 一句话总结

让用户在多链世界中找到正确的链——这个动作本身就是产品失败的标志。好的钱包设计应该让"链"这个概念逐步对用户透明。

## 当前的多链切换体验

### MetaMask 式的手动切换

```
用户操作：
1. 打开 MetaMask
2. 点击网络下拉菜单
3. 寻找目标网络（如果没添加过，需要手动添加）
4. 切换网络
5. 等待切换完成
6. 检查是否显示了正确的资产

常见问题：
- 用户不知道自己当前在哪个网络
- 切换到错误网络后操作失败
- DApp 期望的网络与钱包当前网络不匹配
- 添加新网络需要输入 RPC URL、Chain ID 等技术参数
```

### 改进的自动切换

```
DApp 请求切换网络（EIP-3326）：
await wallet_switchEthereumChain({ chainId: '0xA' }) // Optimism

钱包行为：
- 弹出确认提示："此网站要求切换到 Optimism 网络"
- 用户确认后自动切换
- 如果用户钱包没添加 Optimism，自动提示添加（EIP-3085）
```

## 链抽象的层次

### 层次零：完全手动（当前 MetaMask）

```
用户负担：100%
- 知道自己要操作的链
- 手动切换
- 手动管理各链的 Gas Token
```

### 层次一：智能提示（Rabby、OKX Wallet）

```
用户负担：~70%
- 钱包检测 DApp 期望的网络
- 自动建议切换
- 显示当前账户在所有链上的余额
```

### 层次二：自动路由（部分实现）

```
用户负担：~30%
- 用户表达意图（"转 100 USDC 给 Alice"）
- 钱包自动选择源链（哪条链上有足够 USDC）
- 必要时自动跨链
- 用户只确认最终结果
```

### 层次三：完全抽象（未来）

```
用户负担：接近 0%
- 用户完全不感知"链"的概念
- 余额是统一的（USDC：2000，不分链）
- 操作自动路由到最优链
- Gas 在后台自动管理
```

## 设计要点

### 网络指示器

```
任何时候用户都应该清晰知道：
✅ 当前在哪个网络
✅ 此操作将在哪个网络执行
✅ 资产在哪个网络上

视觉设计：
- 网络名称 + Logo 永远可见
- 不同网络用不同颜色（避免误操作）
- 切换时有明显反馈（动画 + 加载状态）
```

### 错误防护

```
常见错误场景及防护：

场景 1：用户在错误的网络上转账
- 防护：转账前显示"在 Ethereum 上转账给 Alice"
- 警告：如果接收方在历史上只在另一个网络上活跃过

场景 2：往非预期的网络转账
- 防护：跨链转账需要明确选择目标网络
- 警告：选择的网络可能与代币常用网络不匹配

场景 3：在没有 Gas Token 的网络上操作
- 防护：检测后提示"此网络需要 0.001 ETH 作为 Gas"
- 解决：提供"用其他链的资产支付 Gas"选项
```

## 小结

多链切换的最佳设计是"让用户不需要切换"。钱包应该尽可能多地承担"判断在哪条链上做什么"的工作，让用户专注于"想做什么"。完全的链抽象还需要基础设施成熟，但当前已经可以做到大幅降低用户的多链管理负担。
