# 通知与活动流：链上事件的产品化

## 一句话总结

链上发生的事情很多，但用户能消化的有限——好的通知系统是把"海量原始数据"转化为"少量重要信息"的过滤器。

## 用户需要哪些通知

### 高优先级（必须实时通知）

```
- 交易确认（自己发起的交易上链了）
- 大额收款（有人给我转了大额资产）
- 安全警报（异常授权、可疑转出）
- 紧急情况（DeFi 头寸接近清算）
```

### 中优先级（可以延迟）

```
- 小额收款
- DeFi 收益结算
- NFT 出价/报价
- 治理提案投票
- 关注地址的活动
```

### 低优先级（聚合或按需）

```
- 价格变动（持仓资产涨跌幅超过阈值）
- 新空投资格
- 社区活动
- 协议更新
```

## 技术实现

### 数据源

```
通知来源：
1. 交易状态变化
   - 自己发起交易后，监听 receipt
   - 通过 RPC 订阅或轮询

2. 链上事件订阅
   - 订阅地址相关的 Transfer、Approval 事件
   - 通过 WebSocket 实时接收

3. 第三方索引服务
   - Alchemy Webhook
   - Moralis Streams
   - Tenderly Web3 Actions

4. 应用层数据
   - DeFi 协议的健康因子（需要计算）
   - 价格数据（来自预言机或 API）
   - NFT 市场出价
```

### 推送机制

```
移动端：
- iOS APNs / Android FCM
- 需要后端服务持续监听链上事件
- 用户设备 Token 与钱包地址的关联

浏览器：
- Web Push API
- 浏览器关闭时仍可接收（Service Worker）

钱包内：
- 应用内消息列表
- 红点提示
- 不依赖系统推送
```

## 活动流设计

### 信息层次

```
┌─────────────────────────────────────────────┐
│  活动                                        │
├─────────────────────────────────────────────┤
│  今天                                        │
│  ├── 🔄 Swap: 1 ETH → 1,985 USDC           │
│  │   2小时前 · 已确认                       │
│  ├── 📥 收到 500 USDT                       │
│  │   3小时前 · From: alice.eth              │
│  └── ⚠️ 健康因子警告 (Aave)                 │
│      5小时前 · 当前 1.15 (危险)             │
│                                              │
│  昨天                                        │
│  ├── 🖼️ Mint: BAYC #1234                    │
│  ├── 💰 收到质押收益 0.1 ETH                │
│  └── 🗳️ Uniswap 治理投票                    │
│                                              │
│  本周                                        │
│  └── (15 项已聚合)                          │
└─────────────────────────────────────────────┘
```

### 设计要点

```
1. 语义化展示
   ❌ "Transfer 1000000 USDC from 0xAbC..."
   ✅ "向 alice.eth 转账 1 USDC"

2. 时间分组
   按"今天/昨天/本周/更早"分组
   而非简单的时间倒序列表

3. 类型图标
   不同类型用不同图标，便于扫视

4. 状态指示
   - ✅ 已确认
   - 🔄 处理中
   - ❌ 失败
   - ⚠️ 需要关注

5. 关键信息突出
   - 金额（最重要）
   - 对方地址（次要）
   - Gas 费用（次要，可隐藏）
   - 区块号（仅高级用户关心）

6. 可操作
   每条活动可以点击查看详情、复制 hash、查看在区块浏览器
```

## 智能聚合

### 减少噪音

```
原始数据（一周内）：
- 200 笔 USDC 转账（某个机器人空投）
- 50 笔 NFT mint 通知（用户参与多个项目）
- 30 笔 Uniswap V3 LP 头寸更新（自动复利）
- 20 笔小额代币转入（垃圾代币）
- 5 笔正常转账
- 1 次大额收款

如果全部展示：用户被淹没
如果智能聚合：5-10 条有意义的活动
```

### 聚合规则

```
- 同类小额操作：聚合为"X 笔小额转账"
- 同一合约的频繁交互：聚合为"在 Uniswap V3 进行了 N 次操作"
- 已知的垃圾代币：自动隐藏或折叠
- 系统/协议自动操作：标记并折叠
- 用户标记不感兴趣的活动：永久隐藏
```

## 小结

好的通知系统不是"通知更多"，而是"通知更准"。它需要在"信息完整"和"避免打扰"之间找到平衡，并通过智能聚合和优先级排序，让用户在海量链上数据中只看到对自己重要的部分。
