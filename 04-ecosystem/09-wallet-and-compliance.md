# 钱包与合规：KYC/AML 在钱包层的实现

## 一句话总结

随着监管落地，钱包不再是"无监管的自由地带"——合规要求正在重塑钱包产品形态，特别是面向机构和主流市场的产品。

## 监管全景

### 主要法规

```
欧盟 MiCA (Markets in Crypto-Assets)：
- 2024 年生效
- 加密资产服务提供商（CASP）需要授权
- 钱包服务商可能纳入监管范围

美国：
- SEC 关注证券属性
- FinCEN 关注 AML
- OCC 银行级数字资产业务规则
- 各州有不同要求（如 NY BitLicense）

新加坡 PSA / MAS：
- DPT 服务提供商需要 MAS 许可
- 严格的 AML/CFT 要求

香港 VASP：
- 2023 年起持牌制度
- 主要针对交易所，但钱包也可能涉及

中国：
- 加密交易非法
- 钱包服务实际上不可用

其他：
- 韩国：实名制要求
- 日本：FSA 监管
- 印度：高额税收
```

### 钱包面临的合规要求

| 类别 | 要求 | 适用范围 |
|------|------|---------|
| KYC/AML | 用户身份验证、可疑交易报告 | 托管钱包、嵌入式钱包 |
| 旅行规则 | $1000+ 转账需附带身份信息 | 跨 VASP 转账 |
| 制裁筛查 | 不能与制裁地址交互 | 所有商业钱包 |
| 数据保护 | GDPR、CCPA 等隐私法规 | 收集用户数据的钱包 |
| 财务披露 | 用户资产报告（如美国 1099） | 部分托管服务 |
| 反恐融资 | CFT 程序 | 商业钱包 |

## 自托管 vs 托管钱包的合规差异

### 自托管钱包（如 MetaMask、Rabby）

```
监管立场（多数司法区）：
- 不被视为金融机构
- 不需要 KYC 用户
- 不需要监管牌照

但：
- 软件开发者可能仍受软件合规要求约束
- 不能主动协助洗钱（如内置混币器）
- 可能需要遵守制裁筛查（OFAC）
- 美国 FinCEN 曾尝试要求自托管钱包做 KYC（被反对搁置）
```

### 托管钱包（如 Coinbase Wallet 早期、Magic）

```
监管立场：
- 通常被视为金融服务
- 需要 KYC 用户
- 需要 AML 程序
- 需要相关牌照（如 MSB）

要求：
- 用户身份验证
- 可疑活动报告（SAR）
- 客户尽职调查（CDD）
- 制裁筛查
```

### MPC 钱包的灰色地带

```
MPC 钱包的监管定性争议：

如果 2/2（用户 + 服务商）：
- 服务商持有一个分片，能阻止用户操作？
- 是否构成"托管"？
- 可能被视为半托管，需要部分合规

如果 2/3（用户 + 服务商 + 备份）：
- 用户可以绕过服务商
- 不算托管
- 但服务商仍可能被要求合规

实际：监管态度因地区而异，仍在演变中
```

## 钱包的合规功能

### 制裁筛查

```
要求：
- 不能与 OFAC 等制裁名单上的地址交互
- 适用于美国相关的钱包服务
- 影响：发送、接收、Swap 等操作

实现方式：
1. 维护制裁地址数据库（如 Chainalysis、TRM Labs 提供）
2. 交易前检查交易对手地址
3. 命中制裁地址 → 拒绝操作 + 警告

钱包的策略：
- 强合规：默认筛查所有交易
- 弱合规：仅在 UI 提示，不强制阻止
- 无合规：完全不筛查
```

### KYC 集成

```
适用场景：
- 嵌入式钱包（DApp 需要合规）
- 法币出入金通道
- 高额操作

实现方式：
- 集成第三方 KYC 服务（Onfido、Sumsub、Persona）
- 用户完成 KYC 后获得"已验证"标记
- 可以解锁更高限额或特定功能

链上凭证：
- KYC 完成 → 颁发 SBT 凭证
- DApp 可以验证用户的 KYC 状态
- 不需要每个 DApp 重做 KYC
```

### 旅行规则（Travel Rule）

```
要求：
- $1000+（或本地等值）转账需包含双方身份信息
- 主要适用于受监管的服务商

技术方案：
- TRP（Travel Rule Protocol）
- IVMS101 数据格式标准
- Sygna Bridge、Notabene、Veriscope 等中间件

挑战：
- 接收方可能是自托管钱包（无法获取身份信息）
- 不同司法区门槛不同
- 隐私保护与合规的矛盾
```

## 隐私保护与合规的矛盾

### 矛盾本质

```
合规要求：
- 知道谁在转账（KYC）
- 知道转账目的（AML）
- 监控可疑交易

隐私权：
- 财务隐私是基本权利
- 不应该被监控所有交易
- 不应该让所有人看到交易历史

矛盾：链上数据天然公开 + 合规要求加强监控 = 隐私越来越少
```

### 解决方向

```
方向一：选择性披露
- 默认隐私
- 仅在监管要求时披露
- 用 ZK 证明"我满足合规要求"而不暴露细节

方向二：分层隐私
- 小额：完全隐私
- 中额：基本合规
- 大额：完整 KYC

方向三：合规链/合规层
- 在合规链上可以完整 KYC
- 在隐私链上保护隐私
- 跨层桥接需要合规检查
```

## 不同钱包的合规策略

### 完全合规（机构友好）

```
代表：Coinbase Wallet（部分功能）、Fireblocks

特点：
- 严格的制裁筛查
- 可能要求 KYC
- 提供合规报告功能
- 集成法币通道（合规的）

目标用户：机构、企业、合规要求高的用户
```

### 选择性合规

```
代表：MetaMask、OKX Wallet

特点：
- 不主动 KYC 用户
- 但不能与制裁地址交互（OFAC 筛查）
- 法币功能部分有 KYC（通过第三方）
- 不主动报告交易

目标用户：主流加密用户
```

### 抗审查（cypherpunk）

```
代表：Frame、Wasabi（比特币）

特点：
- 不做任何主动合规
- 强调用户主权和隐私
- 可能集成混币、ZK 等隐私工具
- 对监管态度对抗

目标用户：隐私倡导者、抗审查需求
```

## 监管对钱包形态的长期影响

### 可能的演变

```
1. 钱包分层
   - "合规钱包"（KYC + 监管）
   - "自由钱包"（自托管 + 隐私）
   - 不同用户选择不同钱包

2. 嵌入式钱包成主流
   - 因为合规要求让独立钱包难以服务主流市场
   - DApp 成为合规承担方
   - 钱包成为基础设施

3. 链分化
   - 合规链（如 Coinbase 的 Base 倾向合规）
   - 自由链（如部分隐私链）
   - 钱包根据用户合规需求路由到不同链

4. 自托管的不确定性
   - 监管可能加强对自托管钱包的要求
   - 也可能保留自托管的自由
   - 取决于政治和行业博弈
```

## 小结

钱包的合规是一个复杂且不断演变的话题。不同钱包根据目标市场和用户群体，会选择不同的合规策略。

对钱包产品来说：
- **不能完全无视合规**：至少要做制裁筛查（OFAC）
- **需要明确定位**：你是合规优先还是用户主权优先
- **需要法律咨询**：合规是专业领域，不能凭直觉
- **需要持续跟进**：法规在快速变化

合规不一定是负担——做好合规的钱包可以服务机构市场和合规要求高的用户，这是一个有价值的差异化定位。
