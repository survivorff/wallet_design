# 新用户 vs 老用户：需求差异与产品分层

## 一句话总结

新用户和老用户对钱包的需求几乎完全相反——同时服务好两者是产品设计上的最大挑战。

## 需求对比

### 新用户的需求

```
1. 简单
   - 步骤少
   - 概念少
   - 决策少

2. 安全感
   - 不会丢钱
   - 有兜底
   - 可恢复

3. 引导
   - 告诉我下一步做什么
   - 解释概念
   - 推荐操作

4. 即时价值
   - 创建后立刻能用
   - 看到具体的好处
   - 完成首次成功操作
```

### 老用户的需求

```
1. 效率
   - 步骤少
   - 不要打扰
   - 快速完成

2. 控制
   - 完全自主
   - 看到所有细节
   - 自定义一切

3. 深度
   - 高级功能
   - 详细信息
   - 专业工具

4. 安全
   - 不依赖第三方
   - 透明可审计
   - 抗审查
```

### 核心矛盾

```
新用户：要简单 → 隐藏复杂性
老用户：要控制 → 暴露所有细节

新用户：要引导 → 告诉用户做什么
老用户：要自主 → 不要打扰

新用户：要兜底 → 信任第三方
老用户：要主权 → 不信任任何人

如果做一个产品同时满足两者：
不可能完美，必然妥协
```

## 产品策略选择

### 策略一：专注新用户（消费级）

```
代表：Coinbase Smart Wallet、嵌入式钱包

特点：
- 极简设计
- 隐藏技术细节
- 大量引导
- 默认安全设置

牺牲：
- 老用户觉得受限
- 高级功能缺失
- 不够"专业"

适合的市场：
- 主流市场（最大但难赚钱）
- Web2 用户进入 Web3
- 监管要求高的市场
```

### 策略二：专注老用户（专业级）

```
代表：Rabby、Frame

特点：
- 完整的功能
- 详细的信息展示
- 高级安全功能
- 自定义选项

牺牲：
- 新用户上手难
- 学习曲线陡
- 受众规模小

适合的市场：
- 专业用户（小但高 ARPU）
- DeFi 重度用户
- 安全意识强的用户
```

### 策略三：分层服务（妥协）

```
代表：MetaMask、OKX Wallet

特点：
- 提供"新手模式"和"专家模式"
- 默认设置友好新用户
- 高级设置满足老用户
- 通过"展开"暴露细节

挑战：
- 两边都不极致
- 复杂度难管理
- 容易体验割裂

但：覆盖人群最广
```

### 策略四：多产品矩阵

```
代表：Coinbase（同时有 Wallet 和 Smart Wallet）

特点：
- 不同产品服务不同用户
- 通过产品矩阵覆盖所有人
- 每个产品都可以做到极致

挑战：
- 资源分散
- 用户跨产品迁移
- 品牌可能稀释

适合：资源丰富的大公司
```

## 不同阶段的用户旅程

### 用户的成长路径

```
阶段 0：完全新手
- 不知道什么是钱包
- 通过游戏/朋友/媒体接触
- 需求：体验、好奇

阶段 1：尝试者
- 创建了钱包
- 完成了几次操作
- 需求：成功的体验、降低恐惧

阶段 2：活跃用户
- 经常使用
- 用过多个 DApp
- 需求：效率、新机会

阶段 3：进阶用户
- 参与 DeFi、NFT
- 资产规模增长
- 需求：安全、工具、深度

阶段 4：专家用户
- 多链多钱包
- 自己写脚本/工具
- 需求：极致控制、隐私、抗审查

阶段 5：HODLer / 机构
- 大额资产
- 长期持有
- 需求：稳定、安全、合规
```

### 钱包应该陪伴用户成长

```
理想的钱包：
- 新手时简单引导
- 进阶时逐步暴露功能
- 专家时不限制能力
- 机构时提供专业服务

但实际：
- 大多数钱包只服务一个阶段
- 用户成长后会换钱包
- 从产品角度，"留住成长用户"是机会
```

## 渐进式披露的设计

### 核心思路

```
默认：简洁界面，仅核心功能
高级：通过设置或操作解锁更多功能

例子：
默认显示：
- 总余额
- 主要资产
- 简单转账

高级模式（用户主动开启）：
- 多链分布
- DeFi 头寸
- 自定义代币
- Gas 设置
- 原始数据
```

### 实施细节

```
1. 默认隐藏的功能
   - 自定义 RPC
   - 测试网
   - 高级 Gas 设置
   - 原始 calldata
   - 调试工具

2. 渐进暴露的触发
   - 资产规模到一定程度
   - 使用频率到一定程度
   - 用户主动探索
   - 操作复杂度提升

3. 信息密度的层次
   - 卡片视图（新手）
   - 列表视图（普通）
   - 表格视图（专家）
```

## 不同用户群体的指标差异

### 新用户的关键指标

```
- D1 留存
- 首次操作完成率
- Onboarding 完成时间
- 帮助文档查看率
- 客服咨询率
```

### 老用户的关键指标

```
- 月活跃天数
- 平均交易复杂度
- 高级功能使用率
- NPS（推荐意愿）
- 资产规模
```

### 不要混淆

```
错误：
"提升整体留存到 50%"

正确：
"新用户 D7 留存从 30% 提升到 50%"
"老用户月活跃天数从 10 天提升到 15 天"

用户群体不同，指标和优化方向不同
```

## 给产品经理的建议

### 选择你的用户

```
不要试图同时服务所有人：

如果你的资源有限：
- 选择一个用户群体
- 做到极致
- 然后再扩展

如果你的资源丰富：
- 考虑多产品矩阵
- 不要在一个产品中妥协
- 让每个产品都极致
```

### 设计时换位思考

```
设计新用户体验时：
- 假设用户什么都不懂
- 假设用户没有耐心
- 假设用户害怕犯错

设计老用户体验时：
- 假设用户知道一切
- 假设用户讨厌打扰
- 假设用户想要控制
```

### 用数据验证

```
不同用户群体的反馈可能矛盾：
- 新用户："太复杂了"
- 老用户："功能不够"

不要试图同时满足，而是：
- 识别每个反馈来自哪个群体
- 评估你的核心用户群体
- 优先满足核心群体
- 通过其他方式（设置、模式）满足其他群体
```

## 小结

新用户和老用户的需求差异，是钱包产品最根本的设计挑战。没有"通用解"，每个钱包都要在两者之间做选择：

1. **专注一类用户**：可以做到极致，但市场受限
2. **服务多类用户**：覆盖广，但每类都不极致
3. **多产品矩阵**：理想但需要资源

最重要的认知：你不可能同时让所有人满意。识别你的核心用户群体，为他们做最好的产品。其他用户群体可以通过其他方式服务（设置、模式、辅助产品）。
