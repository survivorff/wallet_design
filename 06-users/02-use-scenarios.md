# 用户使用场景分类：交易、DeFi、NFT、社交、GameFi

## 一句话总结

用户用钱包做什么决定了钱包应该是什么——不同使用场景对钱包提出截然不同的产品要求。

## 主要场景分类

### 场景一：交易与投资

```
核心行为：
- 买入/卖出代币
- 持有等待升值
- 跨平台套利
- 跟风操作（跟单 KOL）

钱包需求：
✅ 价格信息及时
✅ 快速 Swap
✅ 多链资产管理
✅ 交易历史和盈亏分析
❌ 不太需要 NFT 功能

代表用户：
- 短线交易者
- 长线投资者
- 套利者
```

### 场景二：DeFi 操作

```
核心行为：
- 流动性挖矿（提供 LP）
- 借贷
- Staking
- 策略协议（如 Curve、Convex）
- Yield farming

钱包需求：
✅ DeFi 头寸聚合展示
✅ 健康因子监控
✅ 收益追踪
✅ 复杂交易支持（批量、Permit）
✅ MEV 保护
✅ Gas 优化

代表用户：
- DeFi 农民
- 套利者
- DAO 成员
```

### 场景三：NFT 收藏与交易

```
核心行为：
- Mint 新项目
- 在市场上买卖
- 出价/接受出价
- 展示和分享

钱包需求：
✅ NFT 美观展示
✅ Mint 体验流畅
✅ 与市场（OpenSea、Blur 等）集成
✅ 稀有度和地板价信息
✅ Gas 抢购优化（Mint 时）

代表用户：
- NFT 收藏家
- NFT 交易者
- 艺术家
```

### 场景四：社交与身份

```
核心行为：
- 用钱包作为身份登录 DApp
- 拥有 ENS / SBT 凭证
- 社交关注（关注其他地址）
- 链上互动（Lens、Farcaster）

钱包需求：
✅ ENS / 域名管理
✅ Profile 展示
✅ 凭证和成就管理
✅ 链上社交集成

代表用户：
- KOL
- 社区参与者
- DAO 治理者
```

### 场景五：GameFi

```
核心行为：
- 游戏内资产交易
- 道具/角色 NFT 管理
- 高频小额交易
- 跨游戏资产移动

钱包需求：
✅ 高频交易支持
✅ Gas 抽象（玩家不应付 Gas）
✅ 嵌入式钱包（游戏内集成）
✅ Session Key（自动签名）
✅ 移动端体验

代表用户：
- 游戏玩家
- Play-to-Earn 用户
```

### 场景六：跨境支付与汇款

```
核心行为：
- 用稳定币支付
- 跨境汇款
- 储蓄（对抗本币贬值）
- 商家收款

钱包需求：
✅ 稳定币支持好
✅ 法币出入金通道
✅ 低费用网络（L2 / Solana）
✅ 收款链接 / 二维码
✅ 简单的转账体验

代表用户：
- 新兴市场用户
- 跨境工作者
- 国际企业
```

### 场景七：DAO 参与

```
核心行为：
- 投票治理提案
- 管理 DAO 资金
- 接收/分发奖励
- 多签操作

钱包需求：
✅ 治理工具集成（Snapshot、Tally）
✅ 多签管理（Safe）
✅ 提案通知
✅ 投票历史

代表用户：
- DAO 成员
- DAO 创始团队
- 治理代币持有者
```

### 场景八：开发与测试

```
核心行为：
- 部署合约
- 与测试网交互
- 调试交易
- 多账户测试

钱包需求：
✅ 自定义 RPC
✅ 测试网快速切换
✅ 多账户管理
✅ 原始数据展示（hex、ABI）
✅ 调试工具集成

代表用户：
- 智能合约开发者
- DApp 开发者
- 安全审计师
```

## 场景对钱包设计的影响

### 不同场景的关键 KPI

```
交易场景：
- 关键指标：Swap 成功率、价格准确性、确认速度
- 优化方向：聚合器、MEV 保护

DeFi 场景：
- 关键指标：头寸数据准确性、健康因子警告及时性
- 优化方向：DeFi 协议覆盖深度

NFT 场景：
- 关键指标：图片加载速度、Mint 成功率
- 优化方向：NFT 索引服务、Gas 抢购

GameFi 场景：
- 关键指标：交易延迟、用户留存
- 优化方向：Session Key、Gas 代付
```

### 单一钱包难以同时优化所有场景

```
矛盾点：
- 交易者要快 vs 安全用户要慢（多次确认）
- DeFi 用户要详细信息 vs 普通用户要简洁
- NFT 用户要图片加载 vs 节省流量
- 游戏用户要免确认 vs 资产用户要每笔确认

解决方案：
- 提供模式切换（"专家模式" vs "新手模式"）
- 根据场景自适应（在 DeFi DApp 显示更多信息）
- 让用户自定义偏好
```

## 多场景用户的钱包组合

### 典型组合

```
重度用户的钱包组合：

钱包 1：MetaMask（DApp 兼容性最广）
- 用于不太熟悉的 DApp 的初次连接
- 大额操作前先用其他钱包

钱包 2：Rabby（安全 + DeFi）
- 日常 DeFi 操作
- 大额交易

钱包 3：Phantom（Solana + NFT）
- Solana 生态
- NFT 操作

钱包 4：Ledger（硬件，长期持有）
- 大额资产
- 不常使用

钱包 5：Safe（多签，团队资金）
- DAO 资金
- 团队资产
```

### 用户为什么用多钱包

```
1. 安全分离
   - 大额放硬件钱包
   - 小额日常用热钱包
   - 实验性操作用一次性钱包

2. 场景适配
   - 不同场景用不同钱包
   - 各取所长

3. 风险隔离
   - 一个钱包被钓鱼不影响其他
   - 不同身份用不同地址

4. 隐私保护
   - 不同活动用不同地址
   - 防止被关联
```

## 给钱包产品的启示

### 选择主攻场景

```
不可能所有场景都做到最好：
- 选择 1-2 个核心场景做到极致
- 其他场景做到"够用"
- 通过差异化建立用户认知

例如：
- Rabby 主攻 DeFi 场景
- Phantom 主攻 Solana NFT 场景
- Safe 主攻 DAO 资金场景
- Coinbase Smart Wallet 主攻新用户场景
```

### 场景延伸

```
从核心场景延伸到周边场景：

Phantom 路径：
NFT → Solana 整体 → 多链
（每一步都基于上一步的用户信任）

Rabby 路径：
EVM 安全 → DeFi 操作 → 多链 EVM → ?
（持续深耕核心人群）
```

## 小结

理解用户的使用场景，比理解钱包的功能更重要。同样的功能在不同场景下的优先级和设计要求完全不同。

钱包产品设计的关键是：
1. 明确目标用户的核心场景
2. 围绕核心场景做到极致
3. 不要试图同时优化所有场景
4. 接受用户会用多个钱包的现实，做好"在某一类场景中最好"

最终的钱包格局是：每个场景都有自己的"场景王"，它们共同构成 Web3 钱包的完整生态。
