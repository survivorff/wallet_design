# Onboarding 漏斗分析：用户在哪一步流失

## 一句话总结

Web3 钱包的 Onboarding 是漏斗最深、流失最严重的产品环节——理解每一步的流失才能针对性优化。

## 完整漏斗

### 传统钱包的漏斗

```
1. 听说钱包概念                100%
        ↓ 流失：30%（觉得复杂、危险）
2. 决定尝试创建钱包             70%
        ↓ 流失：20%（不知道用哪个、怕装错）
3. 选择并下载钱包               56%
        ↓ 流失：10%（安装过程问题）
4. 完成安装                     50%
        ↓ 流失：15%（不愿意创建/被助记词吓退）
5. 创建账户                     43%
        ↓ 流失：30%（抄助记词烦躁、放弃）
6. 完成助记词备份               30%
        ↓ 流失：50%（不知道下一步做什么）
7. 完成首次操作                 15%
        ↓ 流失：60%（再也没用第二次）
8. 7 日活跃用户                  6%
        ↓ 流失：50%
9. 30 日活跃用户                 3%

总转化率：从听说到 30 日活跃 ≈ 3%
```

### 嵌入式钱包的漏斗

```
1. 在 DApp 中看到登录按钮      100%
        ↓ 流失：5%
2. 点击登录                     95%
        ↓ 流失：3%（社交登录失败）
3. 完成社交登录                 92%
        ↓ 流失：2%（钱包创建失败）
4. 钱包自动创建                 90%
        ↓ 流失：30%（DApp 内未引导操作）
5. 完成首次操作                 63%
        ↓ 流失：40%
6. 7 日活跃                     38%
        ↓ 流失：40%
7. 30 日活跃                    23%

总转化率：23%（是传统的 7-8 倍）
```

## 各环节流失原因分析

### 第 1 步：决定尝试

```
流失原因：
- 听说"丢私钥就完了"
- 觉得 Web3 太复杂
- 担心被骗
- 没有明确的使用动机

优化方向：
- 通过具体使用场景吸引（不是抽象的"加密")
- 降低尝试成本（不需要充钱就能体验）
- 提供成功案例（朋友推荐、社区氛围）
```

### 第 2 步：选择钱包

```
用户困惑：
- 钱包种类太多
- 不知道哪个安全
- 不知道哪个适合自己
- 害怕选错

数据：
- ~40% 新用户会问朋友"用哪个钱包"
- 头部钱包靠口碑和默认地位
- 新钱包的获客成本极高

优化方向：
- 简化决策（"如果你用 Solana，选这个"）
- 利用 KOL 和社区
- DApp 推荐合作
```

### 第 3 步：下载安装

```
流失原因：
- 应用商店搜索结果有钓鱼应用
- 浏览器插件需要权限授权
- 下载失败（网络、地区限制）
- 安装包太大（移动端尤其）

优化方向：
- 官方网站清晰的下载链接
- 多渠道分发
- 减小安装包体积
- 应用商店反钓鱼
```

### 第 4-6 步：创建账户和备份

```
最大流失环节，原因复杂：

a) 助记词的恐惧
"12 个英文单词？我必须抄下来？万一抄错了？"

b) 安全教育的副作用
"任何人不能给我看？不能放云端？这怎么备份？"

c) 验证步骤的烦躁
"为什么要我再选一遍？我已经抄下来了！"

d) 不理解为什么
"为什么不能用密码？为什么不能找回？"

优化方向：
- 提供 Passkey / 社交登录替代方案
- 渐进式安全（先创建后再备份）
- 把助记词作为"高级选项"
- 多种备份方式可选
```

### 第 7 步：首次操作

```
"创建完钱包，然后呢？"

流失原因：
- 钱包是空的，不知道做什么
- 不知道怎么"获得"代币
- 法币入金太复杂
- 没有明确的引导
- DApp 连接失败

优化方向：
- Onboarding 内的快速操作引导（领取一个 SBT、完成一个简单交易）
- 法币通道集成（PayPal、Apple Pay）
- 任务系统（完成 X 操作得奖励）
- 与第一个 DApp 深度合作
```

### 第 8-9 步：留存

```
为什么用户不再回来：
- 没有持续使用的理由
- 复杂的操作太累
- 损失了钱（被钓鱼、Gas 费失败）
- 加密市场冷却

优化方向：
- 推送通知召回
- 持续的价值（资产增值、新功能）
- 安全保障（不让用户损失）
- 社区和成就感
```

## A/B 测试和优化

### 关键测试点

```
测试 1：助记词时机
A: 创建时强制备份
B: 创建后立即可用，资产到一定金额再提示备份
结果：B 的完成率高 2-3 倍，但备份率低

测试 2：登录方式
A: 仅助记词
B: 助记词 + Passkey 二选一
C: Passkey 默认，助记词作为"高级"
结果：C 的转化率最高

测试 3：首次操作引导
A: 无引导
B: 详细 tutorial
C: 任务系统（完成任务得奖励）
结果：C > B > A

测试 4：法币入金时机
A: Onboarding 完成后才提示
B: 创建钱包时同时提示充值
结果：B 的"首次操作率"高，但用户感觉"逼着花钱"
```

### 数据驱动的优化

```
钱包应该追踪的关键指标：

漏斗指标：
- 每一步的进入率和完成率
- 流失环节的具体原因（通过用户调研）

留存指标：
- D1、D7、D30 留存
- 不同来源的留存差异
- 不同 Onboarding 路径的留存差异

行为指标：
- 首次操作的类型
- 首笔交易的金额
- 首次返回的时间
```

## 给钱包的建议

### 短期优化

```
1. 减少 Onboarding 步骤
   - 能合并的步骤合并
   - 能延迟的延迟
   - 能跳过的允许跳过

2. 提供多种入口
   - 助记词（传统用户）
   - Passkey（移动用户）
   - 社交登录（Web2 用户）
   - 让用户选择适合自己的

3. 即时价值反馈
   - 创建后立刻给用户"东西"（SBT、空投资格）
   - 让用户感受到"我有了什么"
   - 而不是"我要做什么"

4. 引导式首次操作
   - 不要让用户面对空白页面
   - 提供清晰的下一步建议
   - 任务系统有效
```

### 长期战略

```
1. 嵌入式优先
   - 接受嵌入式钱包是新用户的入口
   - 提供易于集成的 SDK
   - 让 DApp 帮你拉新用户

2. 渐进式去中心化
   - 不强求用户从第一天就完全自托管
   - 提供从托管到自托管的路径
   - 让用户在准备好时升级

3. 教育内容
   - 不要假设用户知道什么
   - 在合适的时机解释概念
   - 用类比和故事而不是技术术语
```

## 小结

Onboarding 漏斗是钱包产品最关键的设计领域。每一步的流失都意味着失去潜在用户，而钱包用户的获取成本极高。

核心原则：
1. **降低门槛**：减少步骤、提供替代方案、延迟复杂性
2. **即时价值**：让用户立即感受到"有了什么"
3. **持续引导**：不要让用户面对空白页面
4. **数据驱动**：追踪每个环节，针对性优化

最大的机会在于：把当前 3% 的总转化率，提升到 20%+ 的水平。这是 Web3 钱包真正主流化的必经之路。
