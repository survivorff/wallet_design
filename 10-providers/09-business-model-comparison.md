# 商业模式与定价横向对比：MAU、签名、抽成三种计费的真实成本

## 一句话总结

Privy 按活跃用户收钱、Turnkey 按签名次数收钱、Crossmint 按链上操作收钱、Fireblocks 走企业议价——选哪家的成本结论，几乎完全由你的"人均月签名数"这一个指标决定。

## 定价一览

| | 免费额度 | 主力计费 | 起步价 | 规模价 |
|---|---|---|---|---|
| **Privy** | 0–499 MAU；所有 Developer 档共享 50K 月签名 + $1M 月交易额 | **MAU 分档**，企业档改为按交易或按交易钱包 | Core $299/月（500–2,499 MAU）<br>Scale $499/月（2,500–9,999 MAU） | 企业档签名可低至 **$0.001** |
| **Turnkey** | 25 次签名（PAYG） | **按签名** | PAYG $0.10/签名<br>Pro $99/月起 | 企业档可低至 **~$0.0015**/签名，钱包数不限 |
| **Fireblocks EW** | 无自助免费层 | **企业议价** | 需销售流程 | 不公开；SLA 99.97%+ |
| **Crossmint** | 有免费层 | **按链上操作**（UserOperation）+ 平台费 | 起步约 $0.05/用户控制钱包/月 | 议价 |

数字来源见文末ï¼其中 Turnkey 与 Privy 的对比数据部分来自双方各自的对比页面(有立场),交叉核对后使用。

## 核心公式：人均月签名数决定一切

这是整篇最有用的一个工具。

```
定义：
  R = 月签名总数 ÷ 月活钱包数
    = 平均每个活跃用户每月签名多少次

  MAU 计费的单位成本 = 每 MAU 价格（不随签名数变化）
  签名计费的单位成本 = R × 每签名价格

分界点：
  每 MAU 价格 = R × 每签名价格
  → R* = 每 MAU 价格 ÷ 每签名价格

R < R* → 签名计费更便宜（Turnkey）
R > R* → MAU 计费更便宜（Privy）
```

### 代入实际报价算一遍

```
情形 A：中等规模，双方公开档位

  Privy Scale 档：$499/月，最多 9,999 MAU
    → 满档时每 MAU ≈ $0.05
  Turnkey Pro：$99/月起 + 较低签名单价，
    假设谈到 $0.02/签名

  R* = 0.05 ÷ 0.02 = 2.5 次/人/月

  → 人均月签名 < 2.5 次：Turnkey 便宜
  → 人均月签名 > 2.5 次：Privy 便宜

注意：Privy 的 Scale 档只含 50K 月签名。
  9,999 MAU × 2.5 次 ≈ 25K 签名，还在额度内。
  但 9,999 MAU × 10 次 = 100K 签名 → 超额，转用量计费。
  → Privy 的分档保护是有条件的，别只看月费。
```

```
情形 B：大规模，企业议价

  Privy 企业档：$0.001/签名（或按交易钱包议价）
  Turnkey 企业档：$0.0015/签名

  这个量级下两家已经接近，
  → 差别不再是定价模型，而是谁给的折扣深、
    以及附加能力（出入金、发卡）值多少钱
```

### 三种典型业务的结论

| 业务类型 | 人均月签名 | 更划算的选择 | 原因 |
|---|---|---|---|
| 空投 / 社交 / 内容打赏 | 1–3 次 | **Turnkey** | 钱包数不限量，签名极少 |
| 稳定币收付 / 汇款 | 5–20 次 | 看议价 | 处于分界区，要实际报价对比 |
| 交易终端 / 游戏 / Agent | 50–1,000+ 次 | **Privy 企业档**或深度议价 | 签名计费会失控 |

一个极端例子:

```
一个每天签名 1,000 次的交易 Agent：
  月签名 30,000 次
  × $0.01/签名 = $300/月/个 Agent

按签名计费在这个场景下完全不可行。
必须谈到 $0.0015 那一档（$45/月）
或者换成按钱包计费。

→ 高频场景的第一件事是问清"按钱包计费的报价"，
  而不是优化签名次数。
```

## 各家的商业模式本质

### Privy：钱包是获客，资金流是变现

```
产品线摊开看就清楚了：

  钱包层（获客）
    User wallets / Agent wallets / Treasury wallets
    → 免费层 0–499 MAU，把开发者拉进来

  安全控制层（留存）
    Key management / Policy engine / Roles
    → 越用越深，迁移成本越高

  资金流层（变现）← 真正的钱在这里
    Cards and spend  —— 卡计划直连钱包余额
    Funding          —— 出入金
    Treasury management
    Yield integrations —— 链上收益

判断：
  MAU 订阅费只是入场费。
  真正的收入曲线在出入金费率、发卡交换费分成、
  收益产品的利差。

这也是 Stripe 收购它的全部逻辑——
Stripe 要的不是 SDK 订阅费，是这些资金流。
```

Privy 定价的另一个设计值得注意:

```
三个维度同时设限：MAU + 月签名 + 月交易额

  → 用户少但交易大 → 触发升级
  → 用户多但交易小 → 触发升级

对客户：成本更难预测
对 Privy：收入捕获更充分

尤其"$1M 月交易额"这条：
  它把定价和你的业务规模直接挂钩，
  本质上是一种收入分成的变体。
```

### Turnkey：卖底层能力，用量计费

```
定价哲学：
  钱包数不限，只对"实际用了"收费

  优点：
    ✅ 长尾钱包零成本（大量不活跃钱包不花钱）
    ✅ 成本和业务活动线性相关，好预测
    ✅ 不惩罚用户增长

  缺点：
    ⚠️ 高频场景成本失控
    ⚠️ sessions 功能减少弹窗，但减不了签名次数
       （会话内每笔仍算一次签名）

产品线扩张方向：
  Embedded Wallets / Company Wallets / Key Management
  → Turnkey Verifiable Cloud（可验证计算）

  最后这个是往钱包之外走。
  2026 年 5 月那笔 $12.5M 战略投资的主题就是
  "crypto verifiable compute"，Circle Ventures 参投。
  → 从"钱包公司"转向"可信执行基础设施公司"
```

**一个结构性问题**:Turnkey 的客户长大之后会不会自建?

```
AllScale 就是现实案例（见 05-allscale）：
  150 万钱包，高频支付场景，按签名计费
  → 随规模增长，Turnkey 成本会成为显著支出项
  → 到某个规模，自建或多供应商化会变得划算

Turnkey 的防守手段：
  1. 可验证性（自建很难做到远程证明）
  2. 策略引擎的深度（自建要重做一遍）
  3. 企业档折扣（用价格留住大客户）
  4. 往可验证计算扩展（提高不可替代性）
```

### Fireblocks：EW 是漏斗上游，托管是主业

```
Fireblocks 的收入结构（推断，未披露明细）：

  主业：机构托管与交易基础设施
    交易所、银行、资管、做市商
    按资产规模 / 交易量 / 席位收费
    客单价极高

  嵌入式钱包：
    客单价低得多
    战略价值：
      a) 抓住"未来会变成机构"的高增长 Fintech
      b) 防守（不做就会被 Privy/Turnkey 抢走客户，
         然后连托管一起丢）
      c) 交叉销售（EW 客户长大后需要托管、
         清算、做市连接，全在同一体系）

所以它花钱买 Dynamic 买的不是收入，是漏斗上游。
```

这解释了它的定价策略——**不做自助免费层ï¼因为它不想要长尾开发者**。它要的是能走采购流程、有合规预算的客户。

### Crossmint：按链上操作 + 卖"不锁定"

```
计费：按 UserOperation 等链上操作 + 平台费
  起步约 $0.05/用户控制钱包/月

商业模式的独特之处：
  它卖的不只是能力，是「退出权」

  对企业采购的价值主张：
    "换供应商不用换地址"
    → 这条能过掉采购部门的 vendor lock-in 否决项
    → 拿下 MoneyGram、Western Union 这类客户

企业签名的成本论点：
  用 AWS KMS 做企业钱包签名器
  → 每次签名几分钱，单个密钥支持每秒最多 1,000 次
  → 对比专业托管商的月费订阅（数千美元量级）

  这个对比对自己有利（用按次 vs 按月比），
  忽略了托管商打包的保险、合规报告、司法区覆盖。
  但对交易量不大的企业客户，性价比确实好。

产品线：钱包 → 稳定币编排 → 代币化
  → 也在往"钱包之外"扩，方向是稳定币资金流
```

## 一个反直觉的观察：四家都在往同一个地方走

```
Privy：      钱包 → 出入金 / 发卡 / 收益 / 资金管理
Turnkey：    钱包 → 可验证计算 / 企业钱包
Fireblocks： 托管 → 钱包 → 全栈数字资产基础设施
Crossmint：  钱包 → 稳定币编排 / 代币化 / 资金管理

共同方向：从"卖钱包能力"往"卖资金流能力"走
```

原因很简单——**钱包 SDK 的 ARPU 撑不起一家大公司**。

```
算一下：
  一个有 1 万 MAU 的中型 DApp
  Privy Scale 档 $499/月 = 年费 $6,000

  要做到 $1 亿年收入，需要约 16,000 个这样的客户。
  但全世界有这个体量的 Web3 应用远不到 16,000 个。

结论：单卖 SDK 的天花板很低。
      要么往上做资金流（抽成、利差、交换费），
      要么被有支付网络的公司买走。

2025 年的三起并购
（Stripe→Privy、ConsenSys→Web3Auth、Fireblocks→Dynamic）
就是这个逻辑的直接结果。
```

## 应用层的单位经济：更难的那道题

基础设施层的定价好算ï¼应用层的钱好不好赚是另一回事。

### 三家应用层公司的收入模型

| | AllScale | Infini | Karsa |
|---|---|---|---|
| 主要收入 | 交易抽成（发票/工资单/Checkout）+ 通道费差 + 余额利差 | 收单费率 + 卡交换费分成 + 余额利差 | 兑换价差 + 付款手续费 + 卡分成 |
| 公开费率 | 未披露 | **收单 0.20%–0.40%（分层）；卡/Apple Pay 收单 3.90%–4.10%；无月费；无托管费** | 早期强调低费/免费兑换 |
| 主要成本 | Turnkey 签名费 + 支付通道 + gas + 合规 | 卡组织与收单行成本 + 托管（Cobo）+ 合规 | P2P 交易商价差 + 上游持牌合作方 + 合规 |
| 托管模型 | 非托管 | 托管 | 推断为托管型 |

### AllScale 的单位经济：一个真实的算术

```
已知：1.5M 钱包，日交易额 $500K

  人均日交易额 = $500,000 ÷ 1,500,000 ≈ $0.33

假设 1% 抽成：
  日毛收入 ≈ $5,000
  年化毛收入 ≈ $180 万

同时的成本：
  1.5M 钱包每月的签名量 × Turnkey 单价
  + 卡收单成本（Checkout 里最贵的一块）
  + gas + 合规

结论：典型的"用户增长快、单用户价值低"阶段。
      要盈利必须让人均交易额上一到两个数量级。

路径：
  客群升级（个人 → 企业）
  场景升级（转账 → 收单 / 发卡 / 收益）
  ← 这正是它产品线扩张的方向
```

### 对照：Infini 的费率哪块赚钱

```
稳定币收单 0.20%–0.40%
  成本：只有 gas
  → 接近纯毛利
  → 对比传统跨境支付 3%–8% 全包成本，
    这是它的核心价值主张

卡 / Apple Pay 收单 3.90%–4.10%（基础费率 + 3.7%）
  成本：卡组织 + 收单行大约 2%–3%
  → 留存空间有限
  → 而且比 Stripe 的 2.9% + $0.30 更贵
  → 卖点只能是"一个平台同时收卡和收稳定币"，不是价格

分层设计（0.40% → 0.30% → 0.20%）
  达标条件是"月交易额或余额"任一满足
  → 同时在争交易量和存款余额
  → 余额更值钱：是利差来源，也是转换成本
```

### 应用层的共同难题

```
1. 稳定币支付的费率天花板很低
   传统跨境 3%–8% 的痛点是真的，
   但一旦你用 0.2%–0.4% 去打，
   毛利空间就被自己压死了。

2. 卡业务不赚钱，但必须做
   卡收单和发卡的毛利薄（要分给卡组织和发卡行），
   但它是"能花出去"的唯一途径，不做产品不完整。

3. 真正的毛利在余额
   余额利差 + 收益产品是最赚钱的部分。
   但这一块的监管风险最高
   （可能触发证券认定、托管牌照要求），
   而且 Infini 事故正是发生在这一块。

4. 获客成本 vs 生命周期价值
   新兴市场用户的 ARPU 低，
   靠自然增长和口碑才划算，
   付费买量基本跑不通。
```

## 选型的成本清单：别只看报价

真实成本远大于供应商报价。

```
供应商报价                        ← 你唯一会比的那项
+ 你要自己补的工程量
    Turnkey：前端 UI、资产索引、出入金
    Fireblocks：user share 保管方案、多设备、备份 UX
    Crossmint：合约钱包相关的兼容性处理
+ Gas 成本
    Crossmint 的 UserOperation 开销
    赞助 gas 的话，这笔钱是你付
+ 集成与上线工期
    Privy 最快，Fireblocks 最慢（含采购流程）
+ 合规与审计成本
    Fireblocks / Turnkey 帮你省最多
+ 三年后的迁移成本
    EOA 路线：季度级项目
    Crossmint：一次配置更新
+ 供应商风险溢价
    Privy → 几乎零（Stripe 背书），但要接受生态绑定
    Fireblocks → 几乎零，但整合期有不确定性
    Turnkey → 中等（独立公司）
    Crossmint → 中等（融资体量最小）
```

## 决策建议

```
先算一个数：R = 月签名数 ÷ 月活钱包数

R < 3（低频）
  → Turnkey 大概率最便宜（钱包不限量）
  → 但要评估自建前端的工程量

R 在 3–20（中频，多数稳定币支付场景）
  → 拿两家实际报价对比
  → 别忘了把 Privy 的出入金/发卡能力折算成
    你自己做要花的钱

R > 20（高频：交易、游戏、Agent）
  → 直接问按钱包/按交易计费的报价
  → 按签名计费在这个区间会失控

无论 R 是多少，如果满足以下任一条，覆盖上面的结论：
  - 要向监管证明密钥架构 → Fireblocks 或 Turnkey
  - vendor lock-in 是硬否决项 → Crossmint
  - 你是 Stripe 的竞争对手 → 排除 Privy
  - 未来要做机构托管 → Fireblocks
```

## 小结

这个赛道的定价格局可以概括成一句话:**基础设施层的定价模型是同一个问题的三种切法(按人、按次、按操作),而它们全都在往资金流变现走ï¼因为单卖 SDK 的天花板太低。**

对客户来说ï¼最实用的判断工具就是那个 R 值(人均月签名数)。它一个数就能定下 Privy 和 Turnkey 之间的成本结论ï¼剩下的决策因素(合规、可迁移性、生态站队)都是能否推翻这个结论的否决项ï¼而不是同等权重的加分项。

对应用层来说ï¼题更难。稳定币支付把费率打到 0.2%–0.4% 之后ï¼毛利只能靠规模、余额利差和卡分成——而余额利差恰好是监管风险最高、Infini 事故发生的地方。AllScale 人均日交易额不到半美元这个数字ï¼说明这一层的单位经济普遍还没跑通。

真正的开放问题在两层的交界处:**当应用层规模长大ï¼基础设施层的按量计费会不会把客户逼向自建?** AllScale 和 Turnkey 的关系ï¼大概会在未来两三年给出答案。
