# Infini 剖析：托管路线的企业卡平台，与一次 4950 万美元的教材级事故

## 一句话总结

Infini 走的是彻底的托管路线，产品做得很实（企业卡 + 收单 + 支出管理 + AI 记账，费率透明到小数点），但 2025 年 2 月那次因内部人员保留管理员权限导致的 4950 万美元被盗，把托管模型最深的那个风险摆到了所有人面前。

## 基本档案

| 项目 | 信息 |
|---|---|
| 定位 | AI 驱动的全球企业财务平台（稳定币金融 OS） |
| 起点 | Web3 信用卡 / 稳定币新银行，起源于香港 |
| 托管模型 | **托管**。事故后资金存放于 Cobo 的托管钱包 |
| 主要产品 | 企业卡（含虚拟卡）、收单（crypto + 卡）、批量付款、支出管理、AI 财务助手 |
| 收费 | 无月费/订阅费，按成功交易计费 |
| 关键事件 | 2025 年 2 月 24 日被盗 $49.5M USDC |

## 技术与资金架构

### 核心模型：托管，且明确托管

Infini 和本章其它公司最大的区别是它不假装非托管。

```
AllScale：非托管，Turnkey 子组织隔离，架构上动不了用户钱
Karsa：  托管型账户 + 链上结算
Infini： 托管。事故后明确资金放在 Cobo 托管钱包

托管带来的产品优势是真实的：
  ✅ 发卡需要能实时扣款 → 托管最顺
  ✅ 收单需要即时结算 → 托管最顺
  ✅ 批量付款、支出管理 → 托管最顺
  ✅ 用户体验完全 Web2，无签名、无 gas、无助记词

托管带来的风险也是真实的：
  ⚠️ 单点故障
  ⚠️ 内部人风险
  ⚠️ 挪用与偿付能力风险
  ⚠️ 监管上可能被认定为需要牌照的托管服务
```

### 事故后的架构调整

```
2025 年 2 月 25 日（事故次日）官方公告要点：

  - 资金当时存放在 Cobo 的托管钱包
  - 转账、充值、提现、支付等功能保持正常运行
  - 收益分发将在接下来 3–4 周内暂停

架构含义：
  从"自己管合约和资金"转向"用第三方专业托管商"
  → 把托管风险外包给有牌照和保险的机构
```

这是事故后的合理选择ï¼但也说明一件事：**在事故之前ï¼Infini 是自己管着可以被管理员权限操作的合约资金的**。

## 那次事故：值得当教材反复读

### 事实链条

```
时间：2025 年 2 月 24 日
损失：$49.5M USDC
来源：Morpho MEVCapital Usual USDC Vault
分两笔转出：约 $11.45M + 约 $38.06M

资金流向：
  USDC → DAI → 17,696 ETH → Tornado Cash

攻击者地址由 Tornado Cash 出资
（说明攻击是有准备的，不是机会主义）

后续：2026 年初仍有约 15,470 ETH 通过 Tornado Cash 洗出
```

### 根因：不是密码学问题，是权限治理问题

```
公开报道指向的根因：

  一名参与过合约开发的工程师
  在离开相关职责后仍保留了合约的管理员级权限
  → 用这个权限把 Vault 里的 USDC 转走

安全公司 Cyvers、Blocksec 确认了攻击事实。
报道还提到该工程师因 100 倍杠杆合约爆仓
背负高息借贷，存在明显的内部人作案动机。

创始人 Christian 当时公开表示：
  被盗的 5000 万里约 70% 属于他认识的朋友
并提出 20% 赏金 + 法律豁免，换取归还资金。
```

### 为什么这个案例特别有教学价值

因为它**不涉及任何高级技术**。没有零日漏洞，没有密码学突破，没有供应链攻击。

```
攻击路径：
  权限没有及时回收 → 完事了

这类风险在传统金融里有成熟的对策：
  - 离职/调岗时的权限回收流程（offboarding）
  - 最小权限原则
  - 特权操作需要多方审批
  - 定期权限审计
  - 时间锁（timelock）+ 紧急暂停

Web3 项目普遍在这一层做得很差，
因为团队来自技术背景而非金融合规背景。
```

### 对照：基础设施层为什么在卖这些功能

把这个事故和前面四家的产品放在一起看，会发现基础设施层卖的正是这个事故缺失的东西：

| 事故缺失的控制 | 哪家的产品直接对应 |
|---|---|
| 特权操作需多方审批 | Turnkey 的 root quorum + REQUIRES_CONSENSUS 策略 |
| 权限按角色最小化 | Turnkey 的 user tags + 策略引擎；Crossmint 的 scoped permissions |
| 权限变更链上可审计 | Crossmint 的链上签名器集合 |
| 单方无法转出资金 | Fireblocks 的真 MPC；Turnkey 的子组织隔离 |
| 签名前策略校验 | Turnkey 的飞地内策略引擎；Privy 的钱包策略 |

**结论**：Infini 事故的每一项失控，在 2026 年都是可以买到的现成产品能力。这也解释了为什么策略引擎成了所有基础设施厂商的标配卖点。

## 业务架构

### 产品线

```
企业卡
  实体卡 + 虚拟卡
  用途隔离：员工、订阅、广告投放、云服务、供应商、单个项目
  → 不用共享一张公司卡号
  Pro Card：1% 外汇费，1.5% 无上限稳定币返现

收单（Acquiring）
  稳定币收单
  卡 / Apple Pay 收单
  支持多个主流钱包和 Binance Pay

资金操作
  批量付款（payouts）
  支出管理
  多地区支付

AI 层
  AI 财务助手，辅助记账
```

### 定价：透明且分层

Infini 的费率披露算行业里比较清楚的，值得记录。

```
平台费：无月费，无软件订阅费，仅按成功交易收费
托管费：持有稳定币余额不收托管或存储费

收单基础费率（按账户等级）：
  Standard     （月交易额 > $0 或余额 > $0）        0.40%
  Professional （月交易额 > $10万 或余额 > $10万）  0.30%
  Elite        （月交易额 > $100万 或余额 > $100万）0.20%

① 稳定币收单：收基础费率 0.20%–0.40%
   仅成功支付时收取；不含链上网络费和第三方费用

② 卡 / Apple Pay 收单：基础费率 + 3.7%
   → 最终 3.90%–4.10%，最低订单金额 $20
```

### 商业模式解读

```
毛利来源：
  1. 稳定币收单 0.2%–0.4%（几乎纯毛利，成本只有 gas）
  2. 卡收单的 3.7% 加价里的差额
     （实际卡组织 + 收单行成本大概 2%–3%，
       所以留存空间有限）
  3. 卡消费的交换费分成（interchange）
  4. 余额资金的收益利差
     （事故后收益分发曾暂停）

关键洞察：
  稳定币收单 0.2% 对比传统跨境支付的 3%–8% 全包成本
  → 这是 Infini 讲给中小企业的核心价值主张

  但卡收单 3.9%–4.1% 并不比传统方案便宜，
  它的价值在于「一个平台同时收卡和收稳定币」，
  而不是价格。
```

### 分层费率的战略意图

```
Standard 0.40% → Elite 0.20%

阶梯设计成"月交易额或余额"任一达标，
说明它同时在争两件事：
  1. 交易量（做支付的商户）
  2. 存款余额（把资金留在平台的企业）

第二个更值钱——余额是收益利差的来源，
也是转换成本（用户把钱放在这里就不容易走）。
```

### 战略转向：从 C 端卡到 B 端财务 OS

```
早期定位：Web3 信用卡 + 理财（C 端为主）
现在定位：AI 驱动的全球企业财务平台

转向原因（推断）：
  1. C 端加密卡赛道竞争极其激烈
     （KAST、Bleap 等一堆玩家，且价格战）
  2. C 端理财产品正是事故发生的地方，
     监管和信任成本都高
  3. B 端客单价高、留存好、监管路径更清晰
  4. 中小企业跨境支付 3%–8% 的痛点是真的
```

这个转向在商业上是合理的。**从被盗资金所在的 Vault 理财业务ï¼转向企业支付和卡业务ï¼同时把托管交给 Cobo,是一次系统性的风险重构。**

## 批判性分析

### 优势一：托管带来的产品完整度

```
发卡、收单、批量付款、支出管理这些功能，
在非托管架构下做起来困难得多：
  - 每笔卡消费都要用户签名？不可能
  - 实时扣款需要平台能动用余额

所以 Infini 的托管选择不是偷懒，是产品需求决定的。
```

### 优势二：费率透明度高于行业平均

明确写出 0.20%/0.30%/0.40% 分层、卡收单加价 3.7%、最低订单 $20、无托管费——这种披露程度在加密支付领域不常见ï¼是加分项。

### 优势三：完成了一次真实的风险重构

```
事故 → 换第三方托管 → 暂停收益产品 → 转向 B 端支付

很多项目出事后是遮掩或直接死掉，
Infini 做了架构和业务的双重调整并继续运营。
执行力上这是可以承认的。
```

### 局限一：信任赤字是结构性的

```
$49.5M 被盗，且根因是内部人权限
→ 这不是"我们运气不好被黑客盯上"
→ 这是"我们的内控有洞"

对一个要求企业把资金存放在平台上的产品，
这是最难修复的一类损伤。

而且它选的是托管模型，
恰好是最需要信任的那一种。
```

### 局限二：托管风险只是转移了，没有消除

```
资金从"自己管的合约"移到"Cobo 的托管钱包"

改善的：
  ✅ 专业托管商有更成熟的内控和权限治理
  ✅ 可能有保险覆盖
  ✅ 可能有牌照

没有改善的：
  ⚠️ 用户对 Infini 仍然只是债权关系，不是所有权
  ⚠️ Infini 若出现偿付问题，用户依然受损
  ⚠️ Cobo 本身成为新的单点
  ⚠️ 账户冻结风险依然存在
```

对照 AllScale 的自托管模型（见 [05-allscale](./05-allscale.md)）：**AllScale 的用户即使 AllScale 消失也能拿回资产ï¼Infini 的用户不能**。这是两种模型最本质的差别。

### 局限三：卡收单费率没有竞争力

```
3.90%–4.10% 的卡收单
对比 Stripe 等传统收单商的 2.9% + $0.30

Infini 更贵。

它的卖点只能是"稳定币结算"和"一个平台两种收款"，
不能是价格。对价格敏感的商户会选传统方案。
```

### 局限四：信息披露不完整

```
公开信息里缺失的关键项：
  ❓ 融资金额和投资方（未完整披露）
  ❓ 用户数 / 交易额规模
  ❓ 事故损失的最终处置结果（用户是否全额补偿）
  ❓ 收益产品资金的具体部署去向
  ❓ 持有哪些司法区的牌照

对一个托管型金融平台，
这几项恰好是尽调时最该看的。
披露不足本身就是一个风险信号。
```

## 什么情况下会考虑 Infini

```
可能适合：
  ✅ 跨境中小企业，需要一个平台同时收稳定币和卡
  ✅ 需要给团队发大量虚拟卡做支出隔离
  ✅ 交易量大能进 Elite 档（0.20% 收单很有竞争力）
  ✅ 能接受托管，且资金规模在可承受损失范围内

需要谨慎：
  ❌ 大额资金长期存放（托管风险 + 历史事故）
  ❌ 对合规要求严格的受监管企业
     （牌照信息披露不足）
  ❌ 主要需求是卡收单价格（比传统方案贵）
  ❌ 需要资产自主权的用户

尽调必问：
  - 事故后的内控改造具体做了什么？有第三方审计报告吗？
  - Cobo 托管的具体安排（隔离账户？保险？）
  - 余额资金是否被部署到 DeFi？部署去向？
  - 持有哪些牌照？覆盖哪些司法区？
  - 用户资金是否与运营资金隔离？
```

## 小结

Infini 是这一章里最矛盾的一个案例：**产品做得挺实，费率披露得挺清楚，转型判断也对，但它同时是行业里最著名的内控失败案例之一。**

它的技术教训一点都不高深:一个不该保留的管理员权限ï¼4950 万美元。这个教训的价值在于它证明了**加密行业最大的风险敞口不在密码学ï¼在权限治理**——而权限治理恰好是传统金融做了几十年、加密行业还在补课的部分。

从产业视角看ï¼Infini 事故加速了两件事：一是策略引擎和权限控制成为钱包基础设施的标配卖点(Turnkey 的 root quorum、Crossmint 的链上权限、Fireblocks 的 MPC 都在卖这个);二是让"自托管"这条路线在稳定币应用层重新有了说服力(AllScale 就是直接受益者)。

某种意义上ï¼这次事故对整个赛道的正面影响ï¼可能比 Infini 自己产品的影响更大。
