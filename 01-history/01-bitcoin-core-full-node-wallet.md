# 起源：Bitcoin Core 与全节点钱包时代

## 一句话总结

最早的加密钱包就是全节点本身——你必须下载整条区块链才能管理自己的比特币。

## 背景

2009 年 1 月 3 日，中本聪挖出比特币创世区块。当时唯一能收发比特币的软件就是 Bitcoin Core（最初叫 Bitcoin-Qt）。这个软件同时承担了三个角色：

1. **全节点**：验证并中继所有交易和区块
2. **矿工**：用 CPU 挖矿（早期）
3. **钱包**：生成地址、管理私钥、构建并签名交易

换句话说，"钱包"这个概念在最初根本不是独立存在的，它只是全节点软件的一个附属功能。

## 技术特征

### 密钥管理

- 每次需要新地址时，随机生成一对新的密钥对
- 私钥存储在本地的 `wallet.dat` 文件中
- 没有助记词，没有 HD 派生，每个地址的私钥彼此独立
- 备份策略：定期复制 `wallet.dat` 文件（如果生成了新地址但没备份，那个地址的币就可能丢失）

### 交易验证

- 完全自主验证：不信任任何第三方，自己验证每一笔交易
- 需要下载完整的区块链数据（2009 年几 MB，如今超过 500 GB）
- 首次同步需要数小时甚至数天

### 架构

```
┌─────────────────────────────────┐
│         Bitcoin Core             │
├─────────────────────────────────┤
│  网络层：P2P 节点通信            │
│  共识层：区块验证、链选择         │
│  存储层：区块数据、UTXO 集       │
│  钱包层：密钥管理、交易构建       │
│  RPC 接口：命令行交互            │
└─────────────────────────────────┘
```

## 用户体验

用今天的标准来看，这个体验可以说是"反人类"的：

- **启动慢**：首次运行需要同步整条链，可能要等几天
- **占用大**：硬盘空间、带宽、内存都有很高要求
- **操作复杂**：命令行或简陋的 GUI，没有现代 UX
- **备份麻烦**：每生成新地址都应该重新备份 wallet.dat
- **无法移动**：只能在运行全节点的那台电脑上使用

但在当时，这些都不是问题——因为用比特币的人本身就是极客和密码朋克，他们享受这种"自己验证一切"的主权感。

## 设计哲学

Bitcoin Core 钱包体现了比特币最原教旨的理念：

- **Don't trust, verify**：不依赖任何第三方，自己验证所有数据
- **完全自托管**：私钥只存在于用户本地
- **隐私优先**：每次交易用新地址，减少地址关联

这套哲学至今仍然是"硬核比特币用户"的信仰，也是后来所有钱包设计的参照原点——后续的每一代钱包，本质上都是在这个原点上做取舍：用一部分"自主验证"换取便利性。

## 历史意义

1. **定义了"钱包"的基本功能**：生成地址、管理私钥、签名交易、广播交易
2. **确立了自托管的基调**：Not your keys, not your coins
3. **暴露了可用性问题**：为后续轻钱包、SPV、HD 钱包的出现埋下了需求种子
4. **证明了去中心化可行**：每个用户都是网络的完整参与者

## 遗留问题

| 问题 | 后续解决方案 |
|------|-------------|
| 同步太慢、占用太大 | SPV 轻钱包（Electrum） |
| 密钥备份麻烦 | HD 钱包（BIP-32/39） |
| 只能在电脑上用 | 移动端钱包 |
| 无法与智能合约交互 | 以太坊钱包（MetaMask） |
| 用户体验差 | 现代钱包的 UX 设计 |

## 关键时间点

- **2009.01**：Bitcoin Core 0.1 发布，内置钱包功能
- **2011**：Bitcoin-Qt 加入图形界面
- **2012**：BIP-32 提出 HD 钱包概念（但 Bitcoin Core 直到 2020 年才支持）
- **2013**：区块链大小突破 10 GB，全节点门槛明显提高
- **2023**：Bitcoin Core 引入 Descriptor Wallet，逐步淘汰旧的 wallet.dat 格式

## 小结

Bitcoin Core 钱包是一切的起点。它不是为"用户"设计的，它是为"网络参与者"设计的。理解这个起点，才能理解后续每一代钱包为什么要做出那些改变——每一次演进，都是在"主权"和"便利"之间重新画线。
