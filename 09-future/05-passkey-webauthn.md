# Passkey 与 WebAuthn：生物识别替代助记词

## 一句话总结

Passkey 让创建和使用钱包变得像解锁手机一样简单——用指纹或面部识别替代助记词，同时保持硬件级的安全性。

## 什么是 Passkey

### 基本概念

```
Passkey = WebAuthn + 平台同步

WebAuthn：W3C 标准，定义了基于公钥密码学的认证协议
Passkey：Apple/Google/Microsoft 对 WebAuthn 的消费级实现，加上跨设备同步

核心特性：
- 密钥对在设备安全芯片中生成
- 私钥永不离开安全硬件
- 用生物识别（Face ID/指纹）授权使用
- 通过 iCloud Keychain / Google Password Manager 跨设备同步
- 抗钓鱼（绑定域名，假网站无法触发）
```

### 技术原理

```
注册流程（创建 Passkey）：
1. 网站/App 调用 WebAuthn API
2. 设备安全芯片生成密钥对（P-256 或 Ed25519）
3. 用户通过生物识别确认
4. 公钥发送给网站/App
5. 私钥存储在安全芯片中（不可导出）

认证流程（使用 Passkey）：
1. 网站/App 发送 Challenge（随机数）
2. 设备用私钥签名 Challenge
3. 用户通过生物识别授权签名
4. 签名发送给网站/App 验证
```

### Passkey vs 传统密钥管理

| | 助记词 | Passkey |
|---|---|---|
| 创建体验 | 抄写 12 个词 | 一次生物识别 |
| 使用体验 | 输入密码解锁 | 生物识别 |
| 备份 | 用户自己保管纸质备份 | 平台自动云同步 |
| 恢复 | 输入助记词 | 登录平台账号 |
| 安全性 | 取决于用户保管能力 | 硬件级保护 |
| 抗钓鱼 | 弱（用户可能在假网站输入） | 强（绑定域名） |
| 跨设备 | 手动导入 | 自动同步 |
| 曲线 | secp256k1 | P-256 (secp256r1) |

## Passkey 用于钱包的挑战

### 核心问题：曲线不匹配

```
以太坊 EOA 使用：secp256k1 (ECDSA)
Passkey 使用：P-256 (secp256r1) 或 Ed25519

问题：Passkey 生成的签名无法直接被以太坊协议验证

解决方案：智能合约钱包（AA）
- 合约钱包的验证逻辑是可编程的
- 可以在合约中实现 P-256 签名验证
- 用户用 Passkey 签名 → 合约验证 P-256 签名 → 操作执行
```

### 架构方案

```
┌──────────────┐     ┌──────────────────┐     ┌──────────────┐
│   用户设备    │     │    EntryPoint     │     │  Account     │
│              │     │    (ERC-4337)     │     │  Contract    │
│  Passkey     │     │                  │     │              │
│  (P-256)     │     │                  │     │  验证逻辑：   │
│              │     │                  │     │  P-256 签名  │
│  签名 UserOp │────→│  提交 Bundle     │────→│  验证        │
│              │     │                  │     │              │
└──────────────┘     └──────────────────┘     └──────────────┘

链上 P-256 验证：
- EIP-7212：预编译合约支持 P-256 验证（部分链已支持）
- Solidity 实现：纯合约实现 P-256 验证（Gas 较高但通用）
- RIP-7212：Rollup 级别的 P-256 预编译
```

### Gas 成本

```
P-256 签名验证的 Gas 成本：

方案 1：纯 Solidity 实现
- ~300,000 Gas（很贵）

方案 2：预编译合约（EIP-7212）
- ~3,000 Gas（与 ecrecover 类似）
- 但需要链支持

方案 3：优化的 Solidity 实现（如 daimo-eth/p256-verifier）
- ~100,000-200,000 Gas

在 L2 上（Base、Arbitrum）：
- 即使是纯 Solidity 实现，Gas 费也只有几美分
- 完全可接受
```

```
创建流程：
1. 用户点击"创建钱包"
2. 系统弹出 Passkey 创建提示
3. 用户 Face ID / 指纹确认
4. 完成（~3 秒）

1. DApp 请求签名
2. 系统弹出 Passkey 使用提示
3. 用户 Face ID / 指纹确认
4. 签名完成

技术栈：
- 账户：ERC-4337 智能合约钱包
- 签名：WebAuthn P-256
- 验证：链上 P-256 验证器
- Gas：Coinbase Paymaster 赞助
- 恢复：Coinbase 作为恢复签名者
```

## 恢复机制

### Passkey 丢失怎么办

```
场景：用户换了手机，且没有开启 iCloud/Google 同步

方案 1：平台同步（默认）
- iCloud Keychain 自动同步到新设备
- Google Password Manager 自动同步
- 只要登录同一个 Apple/Google 账号就能恢复

方案 2：多 Passkey
- 在多个设备上注册 Passkey
- 任何一个设备都可以使用
- 类似"多把钥匙"

方案 3：恢复签名者
- 合约钱包设置一个"恢复地址"
- 可以是另一个 Passkey、硬件钱包、或可信第三方
- 丢失主 Passkey 后，用恢复地址重新注册新 Passkey

方案 4：社交恢复
- 设置多个监护人
- 多数监护人同意即可恢复
- 监护人可以是朋友的 Passkey、硬件钱包等
```

### 信任模型

```
Passkey 钱包的信任假设：

1. 信任设备安全芯片
   - Apple Secure Enclave / Android TEE
   - 如果芯片被攻破，密钥可能泄露
   - 实际风险极低

2. 信任平台同步服务
   - iCloud Keychain / Google Password Manager
   - 如果平台被攻破或配合执法，可能影响恢复
   - 但不能直接获取私钥（端到端加密）

3. 信任合约实现
   - P-256 验证合约的正确性
   - 升级机制的安全性

对比助记词的信任假设：
- 只信任用户自己的保管能力
- 但实际上大多数用户保管得并不好
```

## Passkey 的局限

| 局限 | 说明 | 影响 |
|------|------|------|
| 平台依赖 | 依赖 Apple/Google 的同步服务 | 去中心化程度降低 |
| 曲线限制 | 只支持 P-256/Ed25519 | 需要 AA 钱包 |
| 跨平台 | Apple ↔ Google 同步不完美 | 换生态时可能有问题 |
| 不可导出 | 私钥无法导出 | 无法迁移到其他方案 |
| 浏览器支持 | 部分旧浏览器不支持 | 覆盖率问题 |
| 企业场景 | 不适合多人共管 | 机构用户需要其他方案 |

## 与其他方案的组合

```
Passkey + MPC：
- Passkey 作为一个签名分片
- MPC 服务作为另一个分片
- 双重保护

Passkey + 多签：
- Passkey 作为日常签名者
- 硬件钱包作为高安全签名者
- 大额操作需要两者共同签名

Passkey + Session Key：
- Passkey 作为主密钥
- 为 AI Agent 或 DApp 颁发受限的 Session Key
- 日常操作不需要每次都触发 Passkey
```

## 对钱包行业的影响

### 短期影响

```
- 新用户 Onboarding 体验质的飞跃
- 嵌入式钱包更容易集成（不需要管理助记词）
- AA 钱包的采用加速（Passkey 是 AA 的杀手级应用）
```

### 长期影响

```
- 助记词可能逐渐退出主流用户的视野
- 钱包的安全模型从"用户保管秘密"变为"硬件保护秘密"
- 钱包的竞争焦点从"密钥管理"转向"功能和体验"
- Web3 的用户门槛降低到与 Web2 相当
```

## 小结

Passkey 是目前最有希望让 Web3 钱包达到 Web2 级别用户体验的技术方案。它的核心价值：

1. **零认知门槛**：用户不需要理解任何密码学概念
2. **硬件级安全**：比大多数用户自己保管助记词更安全
3. **原生体验**：与设备的生物识别无缝集成
4. **抗钓鱼**：域名绑定机制天然防钓鱼

代价是引入了对平台（Apple/Google）的信任依赖，以及需要 AA 基础设施的支持。但对于"下一个 10 亿用户"来说，这个权衡是值得的——他们不会也不应该需要管理助记词。
