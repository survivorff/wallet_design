# 签名方案对比：ECDSA vs Schnorr vs EdDSA

## 一句话总结

不同的签名算法在安全性、效率、功能性上各有取舍——选择哪种签名方案直接决定了钱包能做什么、不能做什么。

## 为什么签名方案重要

签名是钱包最核心的操作——每一笔交易、每一次授权、每一个消息验证都依赖签名。签名方案的选择影响：

- 交易大小（影响 Gas 费）
- 验证速度（影响链的吞吐量）
- 功能性（能否原生支持多签、聚合）
- MPC 友好度（能否高效做门限签名）
- 安全假设（依赖什么数学难题）

## ECDSA（Elliptic Curve Digital Signature Algorithm）

### 使用者

Bitcoin、Ethereum、BSC、Polygon 及所有 EVM 链、Cosmos 生态

### 基本原理

```
参数：
- G：椭圆曲线基点
- n：曲线的阶（群的大小）
- d：私钥（随机数，1 < d < n）
- Q = d × G：公钥

签名（对消息哈希 e）：
1. 选择随机数 k（1 < k < n）
2. 计算 R = k × G，令 r = R.x mod n
3. 计算 s = k⁻¹ × (e + r × d) mod n
4. 签名 = (r, s)

验证（已知公钥 Q、消息哈希 e、签名 (r, s)）：
1. 计算 u₁ = e × s⁻¹ mod n
2. 计算 u₂ = r × s⁻¹ mod n
3. 计算 R' = u₁ × G + u₂ × Q
4. 验证 R'.x mod n == r
```

### 特点

| 特性 | 说明 |
|------|------|
| 签名大小 | 64 字节 (r: 32, s: 32) + 1 字节 recovery id |
| 安全性 | 基于椭圆曲线离散对数问题 |
| 标准化 | NIST/ANSI 标准，广泛使用 |
| 随机数依赖 | 签名时需要高质量随机数 k |
| 可延展性 | (r, s) 和 (r, n-s) 都是有效签名 |
| 多签支持 | 不原生支持，需要链上合约或 MPC |

### ECDSA 的关键风险：随机数 k

如果签名时的随机数 k 有问题：
- **k 重用**：两次签名用同一个 k → 私钥可被直接计算出来
- **k 可预测**：私钥可被推导
- **k 有偏差**：通过多个签名的统计分析可能恢复私钥

解决方案：RFC 6979（确定性签名）——从私钥和消息确定性地计算 k，消除随机数风险。

### 以太坊中的 ECDSA

以太坊对 ECDSA 做了一个扩展：签名包含 `v` 值（recovery id），允许从签名恢复公钥：

```
签名 = (r, s, v)  其中 v ∈ {27, 28}（EIP-155 后可能更大）

用途：交易不需要包含发送者公钥，节省空间
从签名恢复公钥 → 计算地址 → 验证是否是声称的发送者
```

## Schnorr 签名

### 使用者

Bitcoin（Taproot 升级后，2021）、部分新链

### 基本原理

```
参数：同 ECDSA（secp256k1 曲线）

签名（对消息 m）：
1. 选择随机数 k，计算 R = k × G
2. 计算 e = Hash(R || Q || m)  （Q 是公钥）
3. 计算 s = k + e × d  （d 是私钥）
4. 签名 = (R, s)

验证：
1. 计算 e = Hash(R || Q || m)
2. 验证 s × G == R + e × Q
```

### 相比 ECDSA 的优势

#### 1. 线性性（Linearity）

Schnorr 签名具有线性性质，这使得签名聚合成为可能：

```
如果 sig₁ = (R₁, s₁) 是密钥 d₁ 对消息 m 的签名
   sig₂ = (R₂, s₂) 是密钥 d₂ 对消息 m 的签名

那么 (R₁ + R₂, s₁ + s₂) 是密钥 (d₁ + d₂) 对消息 m 的有效签名
```

这意味着：
- **多签聚合**：多个签名者可以合并成一个签名，链上只需验证一个签名
- **批量验证**：多个签名可以一起验证，比逐个验证更快
- **隐私**：链上看不出是多签还是单签

#### 2. 可证明安全

Schnorr 签名在随机预言机模型下有严格的安全证明（归约到离散对数问题），而 ECDSA 的安全证明更弱。

#### 3. 无可延展性

ECDSA 的签名可延展（(r,s) 和 (r,n-s) 都有效），Schnorr 没有这个问题。

#### 4. 更简单

Schnorr 的数学结构比 ECDSA 更简单，实现更不容易出错。

### 为什么比特币最初没用 Schnorr

历史原因：Schnorr 签名在 2008 年之前有专利保护（Claus-Peter Schnorr 的专利）。中本聪设计比特币时选择了没有专利问题的 ECDSA。专利 2008 年过期后，比特币社区花了十多年才通过 Taproot 升级引入 Schnorr。

### MuSig：基于 Schnorr 的多签协议

```
MuSig2 协议（2/2 多签示例）：

1. 两个签名者各自生成随机数 R₁, R₂
2. 聚合：R = R₁ + R₂
3. 各自计算部分签名 s₁, s₂
4. 聚合：s = s₁ + s₂
5. 最终签名 (R, s) 与普通 Schnorr 签名无法区分

链上效果：看起来就是一个普通的单签交易
```

## EdDSA（Edwards-curve Digital Signature Algorithm）

### 使用者

Solana、Aptos、Sui、Cardano、Polkadot、NEAR、Stellar

### 基本原理

EdDSA 是 Schnorr 签名在 Edwards 曲线上的变体。最常用的实例是 Ed25519（使用 Curve25519）。

```
曲线：-x² + y² = 1 + dx²y²（扭曲 Edwards 曲线）
具体参数：Curve25519 / Ed25519

签名（确定性，不需要随机数！）：
1. r = Hash(私钥的下半部分 || 消息)  ← 确定性生成
2. R = r × G
3. S = r + Hash(R || 公钥 || 消息) × 私钥
4. 签名 = (R, S)

验证：
检查 S × G == R + Hash(R || 公钥 || 消息) × 公钥
```

### EdDSA 的优势

| 优势 | 说明 |
|------|------|
| 确定性签名 | 不需要随机数，消除了 k 泄露风险 |
| 速度快 | Edwards 曲线运算比 Weierstrass 曲线快 |
| 抗侧信道 | 设计上考虑了恒定时间实现 |
| 小签名 | 64 字节 |
| 批量验证 | 支持高效的批量验证 |
| 简单实现 | 不需要求逆运算 |

### Ed25519 vs secp256k1

| | Ed25519 | secp256k1 |
|---|---|---|
| 曲线类型 | 扭曲 Edwards | Weierstrass |
| 安全级别 | ~128 bit | ~128 bit |
| 签名速度 | 更快 | 较慢 |
| 验证速度 | 更快 | 较慢 |
| 签名大小 | 64 字节 | 64-65 字节 |
| 随机数需求 | 不需要 | 需要（或用 RFC 6979） |
| 生态 | 新链偏好 | BTC/ETH 生态 |
| MPC 友好度 | 较好 | 一般 |
| 硬件支持 | Secure Enclave 原生支持 | 需要软件实现 |

### 为什么新链倾向选择 Ed25519

1. **性能**：签名和验证都更快，对高吞吐链很重要
2. **安全性**：确定性签名消除了随机数风险
3. **硬件支持**：Apple Secure Enclave、Android TEE 原生支持 Ed25519
4. **Passkey 兼容**：WebAuthn/FIDO2 使用 P-256 或 Ed25519
5. **实现简单**：更不容易出实现 bug

## 对钱包的影响

### 多链钱包的挑战

一个多链钱包需要同时支持多种签名方案：

```
EVM 链 → secp256k1 + ECDSA
Solana → Ed25519 + EdDSA
Bitcoin (Taproot) → secp256k1 + Schnorr
Cosmos → secp256k1 + ECDSA（部分链支持 Ed25519）
Polkadot → Ed25519 或 Sr25519
```

这意味着：
- HD 派生需要支持多种曲线
- 签名逻辑需要多套实现
- 硬件钱包需要支持多种算法

### MPC/TSS 的兼容性

不同签名方案对 MPC 的友好度不同：

| 方案 | MPC 友好度 | 原因 |
|------|-----------|------|
| ECDSA | 中等 | 需要复杂的 MPC 协议（如 GG18、GG20） |
| Schnorr | 高 | 线性性使得门限签名自然 |
| EdDSA | 较高 | 类似 Schnorr，但确定性 nonce 需要特殊处理 |

### 账户抽象的意义

ERC-4337 的一个重要价值：**让签名验证逻辑可编程**。

这意味着以太坊上的合约钱包可以使用任何签名方案：
- Passkey（P-256 / secp256r1）
- Ed25519
- BLS（聚合签名）
- 量子抗性签名（未来）

不再被 secp256k1 ECDSA 锁定。

## 未来：后量子签名

量子计算机（如果足够强大）可以破解所有基于椭圆曲线的签名方案。后量子签名方案正在研究中：

| 方案 | 类型 | 签名大小 | 状态 |
|------|------|---------|------|
| CRYSTALS-Dilithium | 格密码 | ~2.4 KB | NIST 标准化 |
| FALCON | 格密码 | ~666 B | NIST 标准化 |
| SPHINCS+ | 哈希 | ~8-50 KB | NIST 标准化 |

挑战：签名大小大幅增加，对区块链的存储和带宽是巨大压力。这也是账户抽象的价值之一——可以在不修改协议的情况下升级签名算法。

## 小结

签名方案的选择不是纯技术决策，它直接影响钱包的功能边界：

- **ECDSA**：历史最悠久，生态最大，但功能受限
- **Schnorr**：数学更优雅，原生支持聚合，比特币 Taproot 的选择
- **EdDSA**：性能最好，最安全（确定性），新链的首选

对钱包开发者来说，理解这些差异才能做出正确的架构决策——尤其是在多链支持、MPC 集成、Passkey 适配等场景下。
