# 密钥管理基础：私钥、公钥、地址的关系

## 一句话总结

私钥是一个随机数，公钥是私钥的单向数学变换，地址是公钥的哈希——这三者的关系是整个加密钱包的数学基础。

## 从随机数到地址

### 完整推导链

```
随机数（256位）
    │
    │ 椭圆曲线乘法（不可逆）
    ▼
公钥（512位，压缩后 257位）
    │
    │ 哈希函数（不可逆）
    ▼
地址（160位 / 不同链有不同格式）
```

每一步都是单向的：
- 知道私钥 → 可以算出公钥 → 可以算出地址
- 知道地址 → **无法**反推公钥 → **无法**反推私钥

这个单向性是整个系统安全的基础。

## 私钥

### 本质

私钥就是一个 256 位的随机数。在数学上，它是椭圆曲线群的一个标量。

```
私钥示例（十六进制，32 字节）：
e9873d79c6d87dc0fb6a5778633389f4453213303da61f20bd67fc233aa33262
```

### 随机性的重要性

私钥的安全性完全依赖于随机性：
- 256 位 = 2^256 种可能 ≈ 10^77
- 宇宙中的原子数量 ≈ 10^80
- 暴力破解在物理上不可能

但如果随机数生成器有缺陷（可预测、熵不足），私钥就可能被猜到。历史上多次资金被盗事件都源于糟糕的随机数生成。

### 私钥的表示形式

| 格式 | 示例 | 说明 |
|------|------|------|
| 原始十六进制 | e9873d79c6d87dc0... | 64 个十六进制字符 |
| WIF (Bitcoin) | 5HueCGU8rMjxEXxiPuD5BDku4MkFqeZyd4dZ1jvhTVqvbTLvyTJ | Base58Check 编码 |
| 助记词 | abandon ability able... | BIP-39 编码（下一篇详述） |
| Keystore JSON | {"crypto":{"cipher":"aes-128-ctr"...}} | 密码加密的 JSON 文件 |

## 公钥

### 椭圆曲线密码学（ECC）

大多数区块链使用 secp256k1 椭圆曲线（比特币和以太坊的选择）：

```
曲线方程：y² = x³ + 7 (mod p)
其中 p 是一个很大的素数

基点 G 是曲线上一个固定的点

公钥 = 私钥 × G（椭圆曲线上的标量乘法）
```

关键性质：
- 知道私钥 k 和基点 G，可以快速计算 k × G
- 知道公钥 P = k × G 和基点 G，**无法**反推 k
- 这就是"椭圆曲线离散对数问题"的困难性

### 公钥的格式

```
未压缩公钥（65 字节）：
04 + x坐标(32字节) + y坐标(32字节)
04 50863ad64a87ae8a2fe83c1af1a8403cb53f53e486d8511dad8a04887e5b2352
   2cd470243453a299fa9e77237716103abc11a1df38855ed6f2ee187e9c582ba6

压缩公钥（33 字节）：
02/03 + x坐标(32字节)
02 50863ad64a87ae8a2fe83c1af1a8403cb53f53e486d8511dad8a04887e5b2352
（02 表示 y 是偶数，03 表示 y 是奇数）
```

为什么可以压缩？因为知道 x 坐标和曲线方程，y 只有两个可能值（一正一负），用一个 bit 就能区分。

## 地址

### 以太坊地址的生成

```
私钥
  │ secp256k1 椭圆曲线乘法
  ▼
公钥（未压缩，去掉 04 前缀，64 字节）
  │ Keccak-256 哈希
  ▼
32 字节哈希值
  │ 取最后 20 字节
  ▼
地址（20 字节 = 40 个十六进制字符）
  │ 加上 0x 前缀
  ▼
最终地址：0x71C7656EC7ab88b098defB751B7401B5f6d8976F
```

### 比特币地址的生成（P2PKH）

```
私钥
  │ secp256k1
  ▼
公钥（压缩，33 字节）
  │ SHA-256
  ▼
32 字节
  │ RIPEMD-160
  ▼
20 字节（Public Key Hash）
  │ 加版本前缀 + Base58Check 编码
  ▼
地址：1BvBMSEYstWetqTFn5Au4m4GFg7xJaNVN2
```

### 不同链的地址对比

| 链 | 曲线 | 哈希 | 编码 | 长度 |
|---|---|---|---|---|
| Bitcoin (P2PKH) | secp256k1 | SHA256+RIPEMD160 | Base58Check | 25-34 字符 |
| Bitcoin (Bech32) | secp256k1 | SHA256+RIPEMD160 | Bech32 | 42-62 字符 |
| Ethereum | secp256k1 | Keccak-256 | Hex | 42 字符(含0x) |
| Solana | Ed25519 | — | Base58 | 32-44 字符 |
| Cosmos | secp256k1 | SHA256+RIPEMD160 | Bech32 | 变长 |

## 签名与验证

### 数字签名的作用

签名证明两件事：
1. **身份**：这笔交易确实是某个私钥的持有者发起的
2. **完整性**：交易内容没有被篡改

### ECDSA 签名流程（简化）

```
签名（私钥持有者执行）：
1. 对交易数据做哈希：h = hash(tx)
2. 生成随机数 k
3. 计算 R = k × G，取 r = R.x
4. 计算 s = k⁻¹ × (h + r × privateKey) mod n
5. 签名 = (r, s)

验证（任何人都可以执行）：
1. 对交易数据做哈希：h = hash(tx)
2. 从签名 (r, s) 和哈希 h 恢复出公钥
3. 检查恢复出的公钥是否与声称的发送者匹配
```

### 以太坊的签名特殊性

以太坊签名包含一个额外的 `v` 值（recovery id），允许从签名直接恢复公钥，而不需要事先知道公钥：

```
签名 = (r, s, v)
其中 v = 27 或 28（表示公钥恢复的两种可能）

这就是为什么以太坊交易不需要包含发送者的公钥——
可以从签名中恢复出来。
```

## 安全要点

### 私钥安全的核心原则

1. **随机性**：必须使用密码学安全的随机数生成器（CSPRNG）
2. **保密性**：私钥绝不能以明文形式暴露
3. **备份**：必须有安全的备份机制（助记词、分片等）
4. **隔离**：理想情况下，私钥不应存在于联网设备上

### 常见的密钥安全问题

| 问题 | 后果 | 防御 |
|------|------|------|
| 弱随机数 | 私钥可被预测 | 使用系统 CSPRNG |
| 明文存储 | 恶意软件可读取 | 加密存储 + 安全硬件 |
| 剪贴板泄露 | 复制私钥时被截获 | 避免复制私钥 |
| 签名时随机数重用 | 私钥可被计算出 | 使用确定性签名(RFC 6979) |
| 侧信道攻击 | 通过功耗/时间推导密钥 | 恒定时间实现 |

## 概念辨析

### "钱包"到底管理的是什么？

一个常见的误解：钱包里"存着"加密货币。

实际上：
- 加密货币存在区块链上（全网共识的账本）
- 钱包管理的是**私钥**（证明你有权操作某个地址的凭证）
- 钱包 = 钥匙串，不是保险箱

```
类比：
银行账户：钱存在银行，你有银行卡和密码
加密钱包：币存在区块链，你有私钥

区别：
银行可以冻结你的账户、重置你的密码
区块链上没有人能冻结你的地址（除非合约层面实现）
私钥丢了就是丢了，没有"找回密码"
```

### 地址 ≠ 账户

在以太坊中：
- **EOA 地址**：由私钥派生，没有代码
- **合约地址**：由部署者地址 + nonce 计算，有代码

两者格式相同（都是 0x + 40 位十六进制），但性质完全不同。

## 小结

私钥→公钥→地址的推导链是所有加密钱包的数学基础。理解这个基础，才能理解后续的一切：为什么助记词能恢复钱包、为什么硬件钱包要隔离私钥、为什么 MPC 要分片、为什么签名能证明身份。

这套密码学体系的优雅之处在于：它用纯数学保证了"只有知道私钥的人才能花费对应地址的资产"，不需要任何中心化的信任。但它的残酷之处也在于：数学不讲情面，私钥丢了就是丢了。
