# 助记词与 HD 钱包：BIP-32/39/44 详解

## 一句话总结

用 12 个英文单词备份无限个地址——HD 钱包用树状派生结构解决了密钥管理的可扩展性问题。

## 问题的起源

早期钱包（Bitcoin Core）的密钥管理方式：

```
地址1 ← 随机私钥1
地址2 ← 随机私钥2
地址3 ← 随机私钥3
...
```

问题：
- 每个地址的私钥彼此独立，必须逐个备份
- 生成新地址后如果没备份，那个地址的资产就有丢失风险
- 无法从一个备份恢复所有地址

## BIP-32：层级确定性钱包

### 核心思想

从一个种子（seed）出发，通过确定性的数学推导，生成一棵密钥树：

```
种子 (Seed)
  │
  ├── 子密钥 0
  │     ├── 孙密钥 0/0
  │     ├── 孙密钥 0/1
  │     └── 孙密钥 0/2
  │
  ├── 子密钥 1
  │     ├── 孙密钥 1/0
  │     └── 孙密钥 1/1
  │
  └── 子密钥 2
        └── ...
```

关键性质：
- **确定性**：同一个种子永远生成同一棵树
- **层级性**：可以无限向下派生
- **单向性**：知道子密钥无法反推父密钥（硬化派生时）

### 派生函数

BIP-32 定义了两种派生方式：

#### 普通派生（Normal/Public Derivation）

```
子私钥 = HMAC-SHA512(父公钥 + 父链码, 索引) 的左半部分 + 父私钥
子链码 = HMAC-SHA512(父公钥 + 父链码, 索引) 的右半部分
```

特点：知道父公钥就能派生子公钥（不需要父私钥）
用途：可以生成"只读钱包"（watch-only），只能看余额不能花费

#### 硬化派生（Hardened Derivation）

```
子私钥 = HMAC-SHA512(父私钥 + 父链码, 索引) 的左半部分 + 父私钥
子链码 = HMAC-SHA512(父私钥 + 父链码, 索引) 的右半部分
```

特点：必须知道父私钥才能派生
用途：防止子密钥泄露时反推父密钥

表示法：硬化索引用 `'` 标记，如 `m/44'/60'/0'`

### 扩展密钥

BIP-32 定义了"扩展密钥"的概念：

```
扩展私钥 (xprv) = 私钥 + 链码
扩展公钥 (xpub) = 公钥 + 链码
```

xpub 可以安全地分享给第三方（如会计软件），让他们追踪所有地址的余额，但无法花费。

## BIP-39：助记词

### 为什么需要助记词

种子是一串 128-256 位的随机数据，人类无法记忆和准确抄写：

```
种子（十六进制）：
5eb00bbddcf069084889a8ab9155568165f5c453ccb85e70811aaed6f6da5fc1
9a5ac40b389cd370d086206dec8aa6c43daea6690f20ad3d8d48b2d2ce9e38e4
```

BIP-39 的解决方案：把种子编码为人类可读的单词序列。

### 编码过程

```
1. 生成随机熵（128/160/192/224/256 位）
   例：128 位 = 16 字节

2. 计算校验和
   checksum = SHA256(entropy) 的前 N 位
   N = entropy位数 / 32
   128位熵 → 4位校验和

3. 拼接：entropy + checksum = 132 位

4. 每 11 位映射到一个单词（2^11 = 2048 个单词的词表）
   132 / 11 = 12 个单词

结果：
abandon ability able about above absent absorb abstract absurd abuse access accident
```

### 熵长度与助记词数量

| 熵（位） | 校验和（位） | 总位数 | 单词数 |
|---------|------------|--------|--------|
| 128 | 4 | 132 | 12 |
| 160 | 5 | 165 | 15 |
| 192 | 6 | 198 | 18 |
| 224 | 7 | 231 | 21 |
| 256 | 8 | 264 | 24 |

大多数钱包使用 12 个词（128 位熵）或 24 个词（256 位熵）。

### 从助记词到种子

```
助记词 → PBKDF2(助记词, "mnemonic" + passphrase, 2048轮, HMAC-SHA512) → 512位种子
```

注意：
- passphrase 是可选的额外密码（"第 25 个词"）
- 相同助记词 + 不同 passphrase = 不同种子 = 不同钱包
- passphrase 可以用来创建"隐藏钱包"（plausible deniability）

### BIP-39 词表

- 2048 个英文单词
- 每个单词的前 4 个字母是唯一的（方便输入）
- 也有中文、日文、韩文、西班牙文等词表
- 英文词表是事实标准，跨钱包兼容性最好

## BIP-44：多币种派生路径

### 路径结构

```
m / purpose' / coin_type' / account' / change / address_index

m          - 主密钥（种子派生的根）
purpose'   - 44'（表示遵循 BIP-44）
coin_type' - 币种编号（BTC=0', ETH=60', SOL=501'...）
account'   - 账户编号（用户可以有多个账户）
change     - 0=外部地址（收款），1=内部地址（找零）
address_index - 地址序号
```

### 常见路径

```
Bitcoin 第一个地址：  m/44'/0'/0'/0/0
Ethereum 第一个地址：m/44'/60'/0'/0/0
Solana 第一个地址：  m/44'/501'/0'/0'（注意：Solana 用硬化派生到底）
Cosmos 第一个地址：  m/44'/118'/0'/0/0
```

### 为什么以太坊通常只用一个地址

比特币的 UTXO 模型鼓励每次交易用新地址（隐私），所以 change 和 address_index 很重要。

以太坊的账户模型下，大多数用户只用一个地址（`m/44'/60'/0'/0/0`），因为：
- 账户模型不需要找零地址
- 一个地址可以持有所有代币
- 多地址管理增加复杂度

但 MetaMask 等钱包支持创建多个账户（`m/44'/60'/0'/0/0`, `m/44'/60'/0'/0/1`, ...）。

## 完整流程示例

```
用户创建钱包：

1. 生成 128 位随机熵
   → 0c1e24e5917779d297e14d45f14e1a1a

2. 编码为 12 个助记词
   → army van defense carry jealous true garbage claim echo media make crunch

3. 用户抄写并安全保存这 12 个词

4. 助记词 + 空 passphrase → PBKDF2 → 512 位种子

5. 种子 → BIP-32 主密钥

6. 主密钥 → m/44'/60'/0'/0/0 → 以太坊私钥 → 公钥 → 地址

7. 用户看到自己的以太坊地址：0x...

恢复钱包：
1. 输入 12 个助记词
2. 重复步骤 4-6
3. 得到完全相同的地址和私钥
```

## 安全考量

### 助记词的安全性

12 个词 = 128 位熵 = 2^128 种可能 ≈ 3.4 × 10^38

暴力破解需要的时间（假设每秒尝试 10 亿次）：
- 2^128 / 10^9 / (365.25 × 24 × 3600) ≈ 10^22 年
- 宇宙年龄 ≈ 1.38 × 10^10 年

结论：128 位熵在当前和可预见的未来都是安全的。

### 常见安全错误

| 错误 | 风险 | 正确做法 |
|------|------|---------|
| 拍照保存助记词 | 云同步泄露 | 纸质抄写，离线保存 |
| 存在电脑文件中 | 恶意软件读取 | 物理介质保存 |
| 只保存一份 | 物理损毁丢失 | 多份备份，不同地点 |
| 告诉别人 | 社会工程攻击 | 永远不分享 |
| 在线输入 | 钓鱼网站截获 | 只在钱包 App 中输入 |

### Passphrase 的作用

```
助记词（公开被盗的情况下）：
- 无 passphrase → 攻击者可以访问默认钱包
- 有 passphrase → 攻击者只能看到空的默认钱包，真正的资产在 passphrase 保护的隐藏钱包中
```

但 passphrase 也有风险：
- 忘记 passphrase = 丢失资产
- 没有"找回 passphrase"的机制

## HD 钱包的局限

| 局限 | 说明 |
|------|------|
| 助记词是单点故障 | 泄露 = 所有地址暴露 |
| 备份负担 | 用户必须安全保存 12/24 个词 |
| 不支持多方控制 | 一个种子 = 一个人的控制权 |
| 恢复时暴露所有地址 | 无法选择性恢复 |
| 跨钱包兼容性问题 | 不同钱包可能用不同派生路径 |

这些局限正是 MPC 和社交恢复等方案试图解决的问题。

## 小结

BIP-32/39/44 三个标准共同构成了现代钱包密钥管理的基石：

- **BIP-32**：定义了从种子派生无限密钥的数学方法
- **BIP-39**：定义了人类友好的种子编码方式（助记词）
- **BIP-44**：定义了多币种、多账户的标准路径

这套体系让用户只需要备份 12 个词就能恢复所有链上的所有地址，是一个优雅的工程解决方案。但它也把所有安全性压缩到了这 12 个词上——助记词的安全就是一切的安全。
